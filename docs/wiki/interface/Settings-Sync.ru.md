# Настройки: Синхронизация

«Библиотека читается из вашего ComfyUI прямо по его адресу или через MCP-сервер, только для чтения. Автосинхронизация и интервал применяются сразу; остальное сохраняет кнопка «Сохранить настройки».» Раздел показывает, как прошла последняя синхронизация, запускает новую, настраивает автоматическую и говорит, как читаются файлы моделей.

## Что он показывает

Состояние и итог: «Синхронизировано · Типов нод: 812, паков: 41, моделей: 331 (с метаданными: 120). Последняя синхронизация: 14:05.» Предупреждения последней синхронизации, приостановленное чтение («Чтение метаданных приостановлено на 120 / 331. Оно продолжится при следующей синхронизации или по кнопке «Синхронизировать сейчас».») и последнюю ошибку.

## Поля и кнопки

| Поле | По умолчанию | Что делает |
|---|---|---|
| **Синхронизировать автоматически** | выключено | Снова читает ComfyUI по таймеру. Работает и с адресом ComfyUI, и с MCP-сервером. Без адреса: «Автоматическую синхронизацию можно включить, когда в разделе «Подключение» указан адрес ComfyUI.» Если прошлая синхронизация не закончилась, автоматическая ждёт, пока вы не нажмёте **Синхронизировать сейчас**. |
| **Интервал, минуты** | 30 | От 5 минут до суток. Число вне диапазона исправляется: «Интервал может быть от 5 минут до суток, поэтому теперь он 5 мин.» |
| **Синхронизировать сейчас** | | Читает ComfyUI прямо сейчас. |
| **Приостановить чтение метаданных** | | Появляется, пока читаются файлы моделей. |
| **Откуда читать метаданные моделей** | **Папки загрузчиков (чекпойнты, LoRA, VAE…)** | или **Все папки моделей** |
| **Моделей в одной порции** | 50 (от 10 до 1000) | Метаданные читаются порциями такого размера, одна за другой, пока не будут прочитаны все файлы. |
| **Пауза между порциями, мс** | 1500 (от 0 до 10 000) | Даёт MCP-серверу и ComfyUI передохнуть. Чтение при этом не прерывается. |

При чтении прямо из ComfyUI приложение получает метаданные из заголовков файлов моделей (название, слово-триггер, базовую модель), но не файлы описаний рядом с ними и не отпечатки; их добавляет MCP-сервер, который читает файлы.

Строка внизу называет постоянный тайм-аут: один вызов MCP может длиться до 60 с. Файл, который не удалось прочитать, не останавливает синхронизацию: он попадает в список **Не удалось прочитать** и читается снова сам через 1 ч, 6 ч, затем 24 ч.

## Проблемы и исправление

Отчёт вынесен в отдельное меню **Синхронизация → Проблемы и исправление**. Кнопка «Показать список» после синхронизации открывает его же. Здесь собраны предупреждения подключения, непрочитанные и исключённые файлы, причины и действия.

- **Повторить сейчас** заново читает конкретный файл через сервер. Работает и для исключённого файла; успешное чтение снимает исключение.
- **Прочитать файл с устройства** открывает выбор файла на устройстве, где открыт интерфейс. Выберите тот же `.safetensors` или `.sft`: проверяются имя, размер и актуальность каталога. Читаются только первые восемь байтов и заголовок до 64 МиБ; веса не загружаются и не передаются. В режиме браузера на телефоне это файл телефона, на компьютере — файл компьютера.
- Читаемый заголовок без описания отмечается как успешно прочитанный без встроенных метаданных. Это не доказательство повреждения. Сохранённое описание из соседнего файла остаётся.
- **Пропускать этот файл** отключает автоматические попытки; ручные действия остаются доступны.
- **Повторить без исключённых** снимает ожидание перед новой попыткой. **Скопировать отчёт** сохраняет причины и исключения в текст.

История показывает заголовки, прочитанные с устройства. Большой заголовок может быть причиной отказа native-маршрута ComfyUI. При смене источника история другого сервера не показывается. Чтение можно приостановить, а настройки подключения открыть прямо из этого окна.
