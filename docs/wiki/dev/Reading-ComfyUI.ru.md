# Чтение ComfyUI

Как приложение узнаёт, какие ноды и модели есть в ComfyUI, никогда его не меняя.

<!-- verify: connection chapter. The connection is being rebuilt; check this page against the connection notes. -->

## Два пути

| Путь | Код | Что читается |
| --- | --- | --- |
| MCP-сервер рядом с ComfyUI (Streamable HTTP) | `src/main/mcp/` | Типы нод, паки нод, папки и файлы моделей, файлы рядом с моделью, отпечаток файла модели, серверы Ollama, которые он запускает. |
| Сам ComfyUI | `src/main/comfy/read.ts` | `GET /object_info` (каждый тип ноды с входами, выходами и допустимыми значениями) и `GET /system_stats`. Только по сохранённому адресу или адресу этого компьютера. |
| Файл | «Файл ▸ Загрузить список нод из файла…» | Ответ `object_info`, сохранённый как JSON. |

## Проверка «только чтение»

Каждый вызов MCP проходит через `readOnlySession` (`src/main/mcp/readOnly.ts`):

- `READ_ONLY_SCHEMAS` перечисляет инструменты, которые приложению можно вызывать, и точную форму их аргументов,
  каждая с `.strict()`, так что лишнее поле отклоняется, а не передаётся дальше.
- Инструменту, который умеет и писать (`workspace_files`), разрешено только действие `read`, только для файла рядом с
  моделью или `pyproject.toml` / `README.md` пака, и действие `hash` только для файла модели.
- Всё остальное бросает `McpRefusedError`, не выйдя из приложения, и попадает в журнал.
- Шлюз, который добавляет приставку к именам инструментов (`gateway_comfy-models`), распознаётся (`detectToolPrefix`),
  и приставка снимается до проверки.

Тесты: `tests/unit/mcpCatalogSafety.test.ts` и тесты синхронизации пробуют все прочие инструменты и формы аргументов.

## Синхронизация

`src/main/mcp/sync.ts`:

1. При запуске (если есть вход или токен и включена автосинхронизация), затем по интервалу или когда человек выбирает
   «Синхронизация ▸ Синхронизировать сейчас».
2. Читает типы нод и паки, затем каждую папку моделей; папка, которая не прочиталась, сохраняет прежний список.
3. Кладёт их в `node_catalog`, `node_packs` и `model_catalog`; вид каталога кэшируется (`cachedCatalog` в
   `src/main/commands/commit.ts`).
4. Читает метаданные моделей в фоне порциями с паузами («Настройки ▸ Синхронизация»), останавливается после
   повторяющихся сбоев и выжидает.
5. Записывает итог в `sync_state` постоянными английскими предложениями, которые окно переводит.

Состояние синхронизации и её ошибки доходят до окна через IPC знаний (`src/main/ipc/knowledgeIpc.ts`).

## Каталог

`src/main/catalog/repository.ts` и `src/main/knowledge/repository.ts` отвечают остальному приложению: типы нод с
полями (`src/shared/catalog/fieldSpec.ts`), модели с семейством и видом (`src/shared/knowledge/baseModel.ts`,
`modelKind.ts`), какой загрузчик читает какую папку (`src/shared/catalog/modelFolders.ts`) и поиск
(`src/shared/knowledge/search.ts`).
