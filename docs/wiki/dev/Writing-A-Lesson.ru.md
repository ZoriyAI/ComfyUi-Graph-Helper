# Как написать урок
Файл курса может содержать до 200 уроков и 16 МиБ JSON в UTF-8; один урок ограничен 8 МиБ. Так весь двуязычный курс можно передать одним файлом, сохранив ограниченное потребление памяти при импорте. Дата проверки содержания относится к редакторской проверке, а не к запуску на GPU. Выполнение и качество результата отмечаются отдельно: правильной структуры графа для этого недостаточно.


Урок это список шагов, и каждый описан как **то, что должно быть на холсте** после него. Приложение читает холст,
чтобы понять, где человек, поэтому урок не хранит своего состояния: удалите ноду, и урок вернётся к её шагу. Как уроки
выглядят для человека: [Как устроены уроки](../lessons/How-Lessons-Work.ru.md). Эта страница о встроенном уроке в коде;
человек делает свой урок в приложении, и такой урок переносится файлом урока:
[Формат файла урока](../lessons/Lesson-File-Format.ru.md).

| Проверка холста | `src/shared/lessons/engine.ts`, `fit.ts` (есть ли в этом ComfyUI то, что нужно уроку), `flow.ts`. |

| Уровень, треки, приоритет | `src/shared/lessons/programme.ts` (`LESSON_PROGRAMME`); виды по уровням, по трекам и путь в `navigation.ts` и `LessonViews.tsx`. |

## Шаг

```ts
{ id: 'model', roles: [node('checkpoint', 'CheckpointLoaderSimple')], fields: [field('checkpoint', 'ckpt_name', chosen)] }
```

- `read: true`: шаг, который только объясняет; человек читает его и идёт дальше. Знание кладите сюда, а шаги с
  действием держите короткими. Шаг для чтения ничего не просит; шаг, который ничего не просит, должен быть шагом для
  чтения.
- `roles`: ноды, которые должны быть на холсте, у каждой имя роли и классы, которые подходят.
- `links`: `link(from, output, to, input, via?)`; `via` перечисляет ноды, которые могут стоять посередине (загрузчик
  LoRA).
- `fields`: `field(role, name, test)`. Проверки (`FieldTest` в `src/shared/lessons/engine.ts`): `chosen`, `equals`,
  `between` (с `prefer`, значение, которое ставит «Сделать за меня»; `frames` для 4n + 1 у Wan), `text` (наименьшая
  длина и настоящие слова, метки, которые он должен содержать, латиница, без «без шляпы»), `weighted` (вес в промпте
  в диапазоне), `file` (файл модели нужного вида), `sameFamily` (LoRA или ControlNet семейства чекпойнта), `size` и
  `aspect` (размер, на котором учили модель), `less`, `same` и `differs` (по сравнению с другим полем) и
  `has-trigger` (слова-триггеры выбранной LoRA).
- `why`: id предложения в `reasons.*.ts`. «Осталось сделать» показывает его, когда значение неверное, чтобы человек
  понял, зачем шагу это значение, а не только что оно неверно.

Пишите собственные имена классов и портов ComfyUI. Урок, чьих классов или входов нет в ComfyUI человека, пишет «Этот
урок пока не подходит к вашему ComfyUI» и называет причины, а не даёт неверных указаний.

## Шаги, на которые отвечает человек
Приложение никогда не запускает workflow и не видит картинок. То, что происходит в ComfyUI, либо уже читается
приложением, либо остаётся словом человека, и шаг говорит, что именно. Четыре вида (`src/shared/lessons/steps.ts`), по
одному на шаг:

```ts
{ id: 'ready', checklist: [{ id: 'comfy', check: { kind: 'comfy-read' } }, { id: 'question' }] },
{ id: 'run', checklist: [{ id: 'ran', run: true }, { id: 'repeat', run: true }] },
{ id: 'complete', readCheck: [{ kind: 'workflow-complete' }] },
{ id: 'assess', rubric: [{ id: 'difference', levels: ['no', 'partly', 'yes'] }, { id: 'blind', levels: ['no', 'yes'], pass: 'yes' }] },
{ id: 'recall', quiz: [{ id: 'cache', choices: ['new', 'cached', 'error'], answer: 'cached' }] },
{ id: 'transfer', transfer: true, roles: [...], links: [...], fields: [...] },
```

- `checklist`: что сделать вне приложения. Пункт с `check` отмечает приложение, пока проверка выполняется; пока
  приложение не может сказать, отметка человека считается его словом; пока проверка не выполняется, отметка не
  считается. `run: true` отмечает доказательство запуска. Пункты `optional: true` шаг не держат.
- `readCheck`: условия, которые приложение проверяет по тому, что уже читает, и никогда не делает для этого своего
  запроса: `comfy-read`, `node-class`, `model-file`, `workflow-complete`, `workflow-size`, `workflow-from` (`picture`
  или `api`), `workflow-partner`. Версии ComfyUI среди них нет: синхронизация её не хранит, поэтому урок спрашивает её
  пунктом списка дел. Пока приложение не может сказать, человек может нажать **Я проверил сам**.
- `rubric`: от двух до четырёх уровней на критерий, от низкого к высокому; `pass` (по желанию) это самый низкий уровень,
  с которым можно идти дальше. Рубрика записывает выбор; картинку приложение не оценивает.
- `quiz`: от одного до пяти вопросов; любой ответ ведёт урок дальше, и показывается объяснение.
- `transfer: true` у шага на холсте или списка дел: нет **Сделать за меня**, а «Осталось сделать» свёрнуто.

Их слова лежат рядом с заголовком и текстом шага: `items` (`label`, `how`), `criteria` (`title`, `levels`, `tryNext`) и
`questions` (`text`, `choices`, `explain`). Движок накопительный: шаг на холсте никогда не противоречит шагу до него
(самостоятельная задача `one-factor` добавляет третий сэмплер, а не меняет второй).

## Исходы
`outcomes: ['structure', 'run', 'result']` говорит, чем урок заканчивается: граф проверен приложением, запуск в ComfyUI
(пункт с `run: true`; собственная проверка приложения, где она есть), результат оценён по рубрике (всегда слово
человека). У урока без `outcomes` только `structure`, и он выглядит как в версии 1.0. Конец урока и его карточка
говорят, какой исход проверило приложение, а какой остаётся словом человека.

## Уровень, треки и приоритет
У каждого встроенного урока есть запись в `LESSON_PROGRAMME` (`programme.ts`): `level` от 0 до 5 (0 установка ComfyUI,
1 основа графа, 2 надёжная практика, 3 картинки, видео, звук и 3D, 4 технические треки, 5 проекты), один или несколько
`tracks` (`base`, `image`, `video`, `audio-3d`, `lora`, `api`, `nodes`, `projects`) и `priority` (`core`, `pro`,
`deep`). Урок никогда не стоит ниже урока, на который опирается (это держит тест). `meta.prerequisites` добавляет ребро
в путь трека; `LESSON_AFTER` по-прежнему говорит, с чьего графа урок начинается.

## Шаблон стандарта 2
У урока со `standard: 2` должно быть (`lessonStandardProblems` в `schema.ts`):

| Часть шаблона | Где |
| --- | --- |
| Один целевой навык | `meta.skill` в словах каждого языка |
| Предусловия | `meta.prerequisites` (id уроков) или `meta.requires` (простые требования) |
| Версии и дата | `meta.versions` и `meta.checkedOn` (ГГГГ-ММ-ДД) в уроке |
| Не меньше трёх ожидаемых ошибок | `meta.mistakes`: `sign` (как узнать) и `fix` (что делать) |
| Запуск, результат, рубрика | пункт списка с `run: true`, `rubric`, `outcomes` |
| Чего приложение не проверяет | `meta.notChecked` |
| Перенос | шаг с `transfer: true` |
| Повторение | `quiz` |
| Происхождение и лицензия | `meta.provenance` |

Все 95 встроенных уроков соответствуют стандарту 2. Импортированные старые уроки стандарта 1 по-прежнему открываются; `node scripts/lesson-lint.js --all` перечисляет недостающие части. Перед поставкой дополнений встроенного курса запускайте `node scripts/lesson-lint.js --all --strict`. Проверка структуры не подтверждает реальный запуск модели или качество её результата.

## Проверка урока: lesson-lint
`node scripts/lesson-lint.js` проверяет встроенные уроки стандарта 2; дайте id уроков или пути к `.lesson.json`, чтобы
проверить их, `--all` для всех встроенных уроков, `--strict`, чтобы падать и на недостающей части. Скрипт печатает каждое
нарушенное правило, каждое недостающее слово пункта, критерия или вопроса, шаг, который нельзя сделать с пустого холста,
и то, что ещё просит шаблон, по одному простому предложению.

## Разобранный пример
`one-factor` (`sets/experiments.ts`) это урок, с которого стоит списывать. Он начинается шагом для чтения; потом список
дел, где два пункта проверяет приложение (`comfy-read`, `model-file`), а один остаётся словом человека; шаги на холсте
с двумя вариантами, которые отличаются только `cfg` (правила `same` на всех остальных настройках второго сэмплера,
`between` с `prefer` и `why` на каждом cfg); проверка, что все ноды установлены; список дел запуска с `run: true`;
рубрика со словами `tryNext`; вопросы; самостоятельная задача на холсте. `blind-compare` продолжает его граф и добавляет
критерий рубрики с `pass`, проверку `workflow-from` и самостоятельную задачу списком дел. Каждый факт о ComfyUI в них
назван в заголовочном комментарии `experiments.ts` вместе с тем, где он подтверждён.

## Рецепт: как написать урок N..
1. Прочитайте строку урока в программе (цель, практика, измеримый результат, приоритет) и решите, какой один навык он
   даёт.
2. Подтвердите каждый факт о ComfyUI, который назовёте, по знаниям приложения (`src/shared/knowledge/`) или официальной
   документации; то, что подтвердить нельзя, сформулируйте так, чтобы урок от этого не зависел.
3. Напишите шаги в файле набора (`src/shared/lessons/sets/<набор>.ts`): шаги на холсте там, где граф может показать
   навык, список дел для того, что происходит в ComfyUI (пункт запуска с `run: true`), `readCheck`, где приложение может
   прочитать факт, рубрику для результата, вопросы, самостоятельную задачу. Поставьте `standard: 2`, `outcomes` и
   `meta`.
4. Напишите слова в `<набор>.texts.en.ts` и `.ru.ts` под теми же id, с `meta` (skill, requires, не меньше трёх
   mistakes, provenance, notChecked) и словами каждого пункта, критерия и вопроса. Причину для каждого числа
   (`reasons.*.ts`) и подпись роли (`lessons.role` в каталоге) для каждой новой роли.
5. Зарегистрируйте набор в `lessons.ts` (`LESSONS` перед уроками для взрослых, `LESSON_PATH`, `LESSON_AFTER`), его слова
   в `texts.en.ts` и `texts.ru.ts`, а место в программе в `programme.ts`.
6. Напишите страницы вики `docs/wiki/lessons/<Name>.md` и `.ru.md` с `<!-- lesson: <id> -->` и добавьте их в оглавление
   уроков.
7. Запустите `node scripts/lesson-lint.js <id>`, потом `npm run type-check` и тесты уроков
   (`tests/unit/lesson*.test.ts`, `lessons.*.test.ts`, `wiki.test.ts` с `WIKI_STRICT=1`, `screenText.test.ts`).

## Какой файл модели

Шаг, который спрашивал только «выбрано ли что-нибудь», засчитывал первый файл списка, каким бы он ни был. Поэтому поле,
куда выбирают файл модели, называет нужный вид:

- `FILES` в `files.ts`: вид с семействами, к которым файл может (или не может) относиться, метками, которые его имя
  должно содержать (`high`, `i2v`, `umt5`) и не должно, папкой внутри `models` и примером имени. Файл судят по
  семейству из его метаданных, иначе по имени; файл, о семействе которого ничего не известно, проверяют только по
  меткам.
- Набор может дать свои виды таблицей слов (`FileRow`: `has`, `any`, `not`): `VIDEO_FILE_KINDS` в `sets/video.ts` и
  `SET_FILE_KINDS` в `fileTables.ts`. `withFileTable` ставит каждую строку в её урок.
- `FAMILY_PAIRS` в `fileTables.ts` держит LoRA или ControlNet в семействе чекпойнта, с которым они работают;
  `withFamilyPairs` ставит правило на место.
- О неверном файле говорится словами человека: у каждого вида есть предложение `lessons.fileKind.<вид>` в каталоге.

## Тексты

Для каждого урока: `title`, `result` (одна строка: что получится у человека) и для каждого id шага короткий `title` и
`body` (небольшой markdown: абзацы, список, `code`). Пишите `{role}`, чтобы назвать ноду урока: приложение подставит
имя ноды так, как его показывает библиотека этого ComfyUI. Простые слова, сначала действие, меню называется так, как
его называет меню. Слово из словаря подчёркивается точками там, где встречается впервые, поэтому объяснять его на месте
не нужно.

## Порядок

- `LESSONS` это порядок, в котором человек их встречает, по группам (`LESSON_PATH`).
- `LESSON_AFTER` говорит, на графе какого урока стоит урок (показывается в списке, но не навязывается).
- Уроки для взрослых (`ADULT_LESSONS`) закрыты переключателем «Настройки ▸ Приватность ▸ Содержимое для взрослых (18+)»
  и видны одной закрытой строкой.

## Тесты

- `tests/unit/lessonSchema.test.ts` прогоняет `lessonProblems` по каждому уроку: id, шаги, роли до использования,
  предложение для каждого `why`, виды файлов, которые знает приложение.
- `tests/unit/lessons.test.ts` и `lessons.<набор>.test.ts` проходят каждый урок с пустого холста до конца, делая то, что
  он говорит, проверяют, что каждый объясняющий шаг показан один раз и что место в уроке читается по графу (удалённая
  нода возвращает назад).
- `tests/unit/lessonFit.test.ts` проверяет, когда урок подходит к ComfyUI, а когда нет; `lessonImageFiles.test.ts` и
  `lessonModel.test.ts` проверяют виды файлов.
- `tests/unit/lessonFiles.*.test.ts` читают, проверяют, хранят, экспортируют и импортируют файлы уроков.
- `tests/unit/wiki.test.ts` проверяет, что у каждого id урока есть страница вики с пометкой `<!-- lesson: <id> -->` на
  обоих языках.
- `tests/e2e/lessons.test.ts` проходит урок в окне.
- `tests/unit/lessonSteps.test.ts` проверяет шаги, на которые отвечает человек, и исходы; `lessonProgramme.test.ts`
  уровни, треки и пути; `lessonFiles.v2.test.ts` версию 2 файла; `lessonLint.test.ts` проверку автора;
  `lessons.experiments.test.ts` уроки-примеры; `tests/e2e/lesson-steps.test.ts` проходит один из них в окне.
