# Выпуск версии

Как версия становится публичной и что пока проверяется только вручную.

## Порядок

1. **Заметки на двух языках.** `docs/releases/vX.Y.Z.md` (по-английски; первая строка ведёт на русский файл) и
   `docs/releases/vX.Y.Z.ru.md`. Абзац под заголовком это краткое содержание. Английский файл становится текстом
   страницы выпуска.
2. **Списки изменений.** `node scripts/changelog.js` пишет `CHANGELOG.md` и `CHANGELOG.ru.md` из заметок; `--check`
   падает, если они устарели (CI его запускает).
3. **Версия.** `npm version X.Y.Z --no-git-tag-version`.
4. **Вики.** `WIKI_STRICT=1 npx vitest run tests/unit/wiki.test.ts` перечисляет каждый комментарий `verify` и
   `skeleton`, оставшийся в документации. Сверьте каждый с кодом; то, что здесь не проверить, страница сама называет
   «пока не проверено», и оно попадает в список ниже. [Как писать страницы справки](Wiki-Style.ru.md)
5. **Ничего личного.** `node scripts/public-tree-check.js` (CI тоже его запускает).
   [Публикация чистой копии](Publishing-A-Clean-Copy.ru.md)
6. **Адрес проекта.** `PROJECT_URL` в `src/main/identity.ts` и `homepage`, `repository`, `bugs` в `package.json`
   называют настоящий репозиторий (`tests/unit/identity.test.ts` их сравнивает); пока этого нет, приложение
   показывает ссылки проекта серыми и ничего не спрашивает о новых версиях.
7. **Выпуск.** Отправьте тег `vX.Y.Z` или запустите сценарий «Build and package» вручную с `release_tag`. Задача plan
   проверяет, что тег, версия в `package.json` и заметки совпадают, и выпуск делается ровно из этого коммита.

## Что запускает сценарий выпуска

`.github/workflows/release.yml` (по тегам, вручную и раз в неделю, если за неделю были коммиты): сквозные тесты; обход
экранов по-русски во всех размерах, по-английски в двух размерах и с более широким текстом при 125 %; четыре пакета
собираются и запускаются, `desktop-file-validate`, `shellcheck`, `lintian`, проверка установленного `.deb`; проверка
обновления с самого нового прежнего выпуска (пропускается с пометкой, если его нет); установка `.rpm` в контейнере
Fedora; `SHA256SUMS` и SBOM; затем в окружении `release` сам выпуск с аттестацией сборки. Каждый запрос на слияние и
каждый пуш проходят быстрые проверки `.github/workflows/ci.yml`. [Форматы пакетов](Package-Formats.ru.md)

## Для страницы репозитория

Описание, сайт и темы для поля «About» на GitHub, картинка для ссылок и настройки, которые может поменять только
владелец, собраны в `docs/REPOSITORY-CARD.md`. Предлагаемое описание в одну строку: «NodeWise Studio: a desktop tutor for
ComfyUI graphs». Темы: `comfyui`, `comfyui-workflow`, `stable-diffusion`, `generative-ai`, `learning`, `tutorial`,
`education`, `node-graph`, `desktop-app`, `electron`, `linux`, `ai-assistant`.

## Ещё не проверено на настоящей установке

Подключение проверено на тестовых серверах, которые говорят как ComfyUI. Прежде чем считать его проверенным,
попробуйте на настоящей машине:

1. ComfyUI, запущенный из своей папки на 8188, и настольное приложение на 8000 оба находятся кнопкой «Найти на этом
   компьютере».
2. ComfyUI в Windows: пути моделей приходят с обратными косыми чертами, подпапки с `\`; превью загружаются.
3. Большая установка (3000 и больше типов нод) читает `/object_info` быстрее 180 секунд.
4. ComfyUI старше адресов `/experiment` показывает только имена моделей.
5. С ComfyUI-Manager и без него: имена паков совпадают с папками в `custom_nodes`.
6. ComfyUI на другом компьютере, запущенный с `--listen`: читается по `http`, подсказки появляются.
7. `/view_metadata` отвечает 404 для файлов без метаданных, и чтение заголовка на этом останавливается.
8. Настоящие artokun/comfyui-mcp и joenorton/comfyui-mcp-server: схемы их инструментов совпадают с тем, что узнаёт
   приложение.
9. На обычных жёстких дисках адрес превью отвечает примерно секунду на файл во время фонового чтения.
10. ComfyUI за прокси со входом: приложение говорит, что адрес ведёт на другую страницу.

Пакеты: установка `.deb` через apt на настоящем рабочем столе, `.rpm` через dnf в Fedora, готовый файл AppImage и
обновление с прежнего выпуска проверяются только в CI.

Остальное, о чём документация говорит «пока не проверено»:

1. Обновление с 0.9 на настоящем рабочем столе: папка с данными переезжает, ключи из GNOME Keyring и из KWallet нужно
   ввести заново, ключи из файла переезжают, а старая запись «Safe Storage» остаётся в хранилище.
2. KWallet как хранилище паролей («Настройки ▸ Приватность ▸ Какое хранилище использует приложение»,
   `--password-store=kwallet5|kwallet6`).
3. Уведомление 0.9 о новой версии против выпуска 1.0, чьи файлы носят новое имя.
4. Настоящий экранный диктор (Orca): имена нод, связей и входов, готовый ответ читается один раз, шаги уроков и
   синхронизация объявляются. [Доступность](../trust/Accessibility.ru.md)
5. Размер интерфейса 200 процентов на экране 1080p с крупным масштабом системы.
6. Строки установки ComfyUI на странице [ComfyUI и где его взять](../start/ComfyUI.ru.md): адрес репозитория и строка
   `torch` следуют официальной инструкции ноября 2026 года, но установки по ним здесь не делалось.
7. Windows: запуск из исходников, пути моделей с обратными косыми чертами, `--version` и `--help`.
   [Сборка и запуск на Windows](Building-On-Windows.ru.md)
8. macOS: запуск из исходников, имя пакета (`NodeWise Studio.app`), недостающий значок `.icns`, имя записи в «Связке
   ключей» (`nodewise-studio Safe Storage`). [Сборка и запуск на macOS](Building-On-macOS.ru.md)
