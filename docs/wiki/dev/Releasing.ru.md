# Выпуск версии

Как версия становится публичной и что пока проверяется только вручную.

## Проверки точных исходников перед публикацией

Публикация ожидает типизацию, lint, полный набор unit-проверок, E2E, обход экранов, Linux-пакеты и вызываемый процесс проверки установщиков Windows/macOS. Все checkout привязаны к `source_sha` этапа планирования. Вызываемая проверка установщиков пропускает независимую проверку прежнего latest-релиза. Пока обязательная проверка выполняется или упала, tag и ручной запуск не публикуют релиз. Для локального/ручного выпуска отдельно фиксируются реально выполненные проверки и непроверенные платформы; само наличие workflow не подтверждает запуск удалённых заданий.


## Порядок

1. **Заметки на двух языках.** `docs/releases/vX.Y.Z.md` (по-английски; первая строка ведёт на русский файл) и
   `docs/releases/vX.Y.Z.ru.md`. Абзац под заголовком это краткое содержание. Английский файл становится текстом
   страницы выпуска.
2. **Списки изменений.** `node scripts/changelog.js` пишет `CHANGELOG.md` и `CHANGELOG.ru.md` из заметок; `--check`
   падает, если они устарели (CI его запускает).
3. **Версия.** `npm version X.Y.Z --no-git-tag-version`.
4. **Вики.** `WIKI_STRICT=1 npx vitest run tests/unit/wiki.test.ts` перечисляет каждый комментарий `verify` и
   `skeleton`, оставшийся в документации. Сверьте каждый с кодом; то, что здесь не проверить, страница сама называет
   «пока не проверено», и оно попадает в список ниже. [Как писать страницы справки](Wiki-Style.ru.md)
5. **Ничего личного.** `node scripts/public-tree-check.js` (CI тоже его запускает).
   [Публикация чистой копии](Publishing-A-Clean-Copy.ru.md)
6. **Адрес проекта.** `PROJECT_URL` в `src/main/identity.ts` и `homepage`, `repository`, `bugs` в `package.json`
   называют настоящий репозиторий (`tests/unit/identity.test.ts` их сравнивает); пока этого нет, приложение
   показывает ссылки проекта серыми и ничего не спрашивает о новых версиях.
7. **Скрипты установки.** Последний запуск «Install scripts» (`.github/workflows/install-scripts.yml`) на коммите
   выпуска зелёный на Windows и macOS: скрипты входят в файлы выпуска, а установка одной командой из README скачивает
   их из последнего выпуска.
8. **Выпуск.** Отправьте тег `vX.Y.Z` или запустите сценарий «Build and package» вручную с `release_tag`. Задача plan
   проверяет, что тег, версия в `package.json` и заметки совпадают, и выпуск делается ровно из этого коммита.

## Что запускает сценарий выпуска

`.github/workflows/release.yml` (пуши main, теги, вручную и раз в неделю, если за неделю были коммиты): сквозные тесты; обход
экранов по-русски во всех размерах, по-английски в двух размерах и с более широким текстом при 125 %; четыре пакета
собираются и запускаются, `desktop-file-validate`, `shellcheck`, `lintian`, проверка установленного `.deb`; проверка
обновления с самого нового прежнего выпуска (пропускается с пометкой, если его нет); установка `.rpm` в контейнере
Fedora; `install-windows.ps1` и `install-macos.sh` копируются в файлы выпуска; `SHA256SUMS` по всем файлам и SBOM;
затем в окружении `release` сам выпуск с аттестацией сборки. `scripts/release-plan.js` не публикует выпуск без двух
скриптов установки и `SHA256SUMS`. Каждый запрос на слияние и
каждый пуш проходят быстрые проверки `.github/workflows/ci.yml`. [Форматы пакетов](Package-Formats.ru.md)

## Для страницы репозитория

Описание, сайт и темы для поля «About» на GitHub, картинка для ссылок и настройки, которые может поменять только
владелец, собраны в `docs/REPOSITORY-CARD.md`. Предлагаемое описание в одну строку: «NodeWise Studio: a desktop tutor for
ComfyUI graphs». Темы: `comfyui`, `comfyui-workflow`, `stable-diffusion`, `generative-ai`, `learning`, `tutorial`,
`education`, `node-graph`, `desktop-app`, `electron`, `linux`, `ai-assistant`.

## Ещё не проверено на настоящей установке

Проверенное состояние на 17 ноября 2026:

- Настоящий ComfyUI 0.45.3: 3375 типов нод, 797/797 прочитанных файлов, прямое чтение при недоступном MCP. [Каталог](https://github.com/ZoriyAI/nodewise-studio/blob/v1.3.0/docs/research/2026-11-17-live-catalog.md).
- 678 официальных workflow прошли сохранение и правку, отдельно проверены реальные формы текущего ComfyUI. [Совместимость](https://github.com/ZoriyAI/nodewise-studio/blob/v1.3.0/docs/research/2026-11-17-native-compatibility.md).
- Настоящая локальная модель прошла построение, паузу, перезапуск и продолжение; native Ollama освободила GPU при выходе. [Агент](https://github.com/ZoriyAI/nodewise-studio/blob/v1.3.0/docs/research/2026-11-17-agent-runtime.md).
- Изолированные окна Electron проверены при 200% на 1080p и 100% на 4K, реальные события AT-SPI и сформированная Orca речь проверены. Это не прослушивание человеком. [Доступность](../trust/Accessibility.ru.md).

Остаётся отдельной приёмкой:

1. Физические Android/iOS и независимое прохождение новичком от установки до своего результата. Эмуляция касаний и проверка всех 50 экранов помощи не заменяют эти сценарии.
2. ComfyUI Desktop, ComfyUI в Windows, пути с обратными косыми чертами и разные версии Manager на реальных установках; старые `/experiment`, медленные диски и прокси со входом.
3. Авторизованные реальные artokun/comfyui-mcp и joenorton/comfyui-mcp-server. При 401 проверен переход к прямому ComfyUI, но не успешный вход в эти серверы.
4. Установка `.deb` через apt на рабочем столе, `.rpm` через dnf на Fedora и AppImage на разных дистрибутивах. CI проверяет установку и обновление; локальная проверка пакета должна отдельно указывать свою изоляцию и предшествующую версию.
5. Миграция 0.9 с настоящими ключами GNOME/KWallet, сами KWallet5/6 и уведомление старой 0.9 о переименованном выпуске.
6. Windows 10/11 и реальные Mac: нелатинское имя пользователя, прокси, системный Node, установка build tools, системные меню/ярлыки, Keychain после обновления и удаление ключей. GitHub проверяет скрипты из точного исходника; это не весь парк устройств. Linux-подсказки хранилища больше не показываются как настройки этих ОС.
7. Полный сценарий с экранным диктором, прослушивание человеком и дополнительные системные масштабы.
8. Повтор установки ComfyUI по опубликованным командам на чистых ОС; реальные учётные данные подписи Windows/macOS и установка подписанных бинарных пакетов.

Новая проверка закрывает только свой конкретный сценарий. Отчёты и выпуск должны сохранять эти границы.
