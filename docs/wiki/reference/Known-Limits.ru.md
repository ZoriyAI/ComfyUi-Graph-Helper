# Известные ограничения

Чего приложение не делает и где оно сегодня слабо. CozyGraph экспериментальный проект; этот список прямо говорит,
чего ждать. Пожелания пишите в обсуждения проекта, о проблемах в обращения (Issues).

## Так задумано

- **Оно никогда не запускает workflow.** Оно собирает и объясняет; запускает ComfyUI.
  [Как запустить результат в ComfyUI](../graph/Running-In-ComfyUI.ru.md)
- **Оно никогда не меняет ComfyUI.** Не ставит ноды и модели, не скачивает файлы и не ставит задания в очередь.
  [ComfyUI только читается](../trust/Read-Only.ru.md)
- **Два языка:** русский и английский.

## Системы и пакеты

- Собирается только пакет `.deb` для 64-битного x86 Linux. Нет AppImage, Flatpak, RPM и пакетов для ARM.
- Windows и macOS: приложение можно собрать из исходников; шаги там не проверялись, и у каждой системы свои
  ограничения. [Windows](../dev/Building-On-Windows.ru.md), [macOS](../dev/Building-On-macOS.ru.md)
- Автоматических обновлений нет: новую версию ставьте сами со страницы Releases проекта.
  [Обновление](../start/Updating.ru.md)

## Подключение и чтение

- Подключение проверено на тестовых серверах, которые говорят как ComfyUI; на настоящей установке ComfyUI оно ещё не
  запускалось.
- Прямо из ComfyUI нет описаний рядом с файлами моделей, README паков и отпечатков, поэтому «Найти в интернете» ищет
  только по имени файла. Их добавляет MCP-сервер, который читает файлы.
  [Что даёт каждый способ](../connect/What-Each-Way-Shows.ru.md)
- Старый ComfyUI сообщает только имена моделей, без размеров и картинок.
- Официальный `comfy-mcp` от Comfy Org запускается как локальная команда и пока не подключается; MCP-сервер с
  незнакомыми приложению инструментами не используется.
- Окно контекста модели на своём сервере читается только у Ollama. Другие серверы его не сообщают; тогда приложение
  замечает, что запрос не поместился, только по счёту токенов в ответе.
- Поиск моделей: Civitai находит файл точно по отпечатку; на Hugging Face поиск идёт по имени файла, и карточка
  говорит, что это догадка. Отпечаток большого файла сервер считает минутами, поэтому при синхронизации он не
  считается.
- Пак нод описывается по его `pyproject.toml` и началу README; пак без них показывается только с именем и версией.
- Когда у облачной модели нет своего поиска, помощник ищет через HTML-страницу DuckDuckGo, и это может сломаться,
  если страница изменится.

## Граф

- Внутри субграфа нельзя сделать новый субграф или группу, а вложенный субграф нельзя растворить: это делается на
  основном холсте. Группы, пришедшие внутри субграфа из ComfyUI, сохраняются при экспорте, но на холсте не
  показываются.
- Новый проект («Файл ▸ Новый проект») начинается в старом формате workflow, в котором субграф сделать нельзя. У
  графа, открытого из свежего ComfyUI, этого ограничения нет. [Субграфы](../graph/Subgraphs.ru.md)
  <!-- verify: remove when New project starts in workflow format 1 -->
- Ноды пока нельзя копировать, вырезать, вставлять и дублировать; `Ctrl+C` и `Ctrl+V` работают только в текстовых
  полях. [Копирование и вставка](../graph/Copy-And-Paste.ru.md) <!-- verify: copy and paste of nodes -->
- Картинки с workflow внутри не открываются; откройте файл workflow `.json`.

## Помощник и уроки

- Помощник строит только на основном холсте. Если открыт субграф, холст возвращается на основной уровень и говорит об
  этом. Уроки тоже идут только на основном холсте.
- Пауза на контрольной точке (лимит шагов) не переживает перезапуск приложения: после перезапуска спросите снова.
- Качество ответов зависит от модели. Маленькие локальные модели с маленьким окном контекста теряют нить длинной
  сборки. [Окно контекста](../assistant/Context-Window.ru.md)
- Уроки по WanVideoWrapper охватывают часть этого пака; у остальных его возможностей уроков нет.

## Доступность

- Ноды и связи на холсте трудно отслеживать экранным диктором, а ответ помощника объявляется по кусочкам, пока
  пишется.
- Масштабируется только холст; остальное окно следует масштабу текста вашей системы.
