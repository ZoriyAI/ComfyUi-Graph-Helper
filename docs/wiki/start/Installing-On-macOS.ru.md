# Установка на macOS

Готового пакета для macOS пока нет. Вместо него в каждом выпуске есть скрипт `install-macos.sh`: он собирает
приложение на вашем Mac из исходного кода проекта и устанавливает его для вас. Всё делает одна команда; на этой
странице сказано, что она делает, о чём спрашивает и как всё отменить.

> **Ещё не проверено.** Этот скрипт появился в 1.0.0 и на настоящих Mac не проверялся; проверка на машинах GitHub с
> macOS есть и ещё доводится до успешного прохода. Если попробуете, сообщите, пожалуйста, что получилось, в обращениях
> (Issues) проекта: приложите файл журнала, который скрипт назовёт в конце (`~/Library/Logs/nodewise-studio-install.log`),
> и версию macOS. Если не получится, есть ручной путь: [Сборка и запуск на macOS](../dev/Building-On-macOS.ru.md).

## Что нужно

- macOS 13 Ventura или новее, на Apple silicon (M1 и новее) или Intel.
- Около 3,5 ГБ свободного места для сборки (в конце она удаляется) и 600 МБ для приложения.
- Доступ в интернет к `github.com`, `nodejs.org` и `registry.npmjs.org`.
- Пароль администратора не нужен, если вы не выбрали `/Applications` или Node.js для всего Mac.

## Одна команда

Откройте **Терминал** (Launchpad ▸ Другие ▸ Терминал) и вставьте:

```bash
curl -fsSL https://github.com/ZoriyAI/nodewise-studio/releases/latest/download/install-macos.sh -o install-macos.sh && bash install-macos.sh
```

На главной странице проекта (README) та же строка показана с настоящим адресом.

## Осторожный способ

1. Скачайте `install-macos.sh` и `SHA256SUMS` со страницы выпуска.
2. Проверьте файл: `grep ' install-macos.sh$' SHA256SUMS | shasum -a 256 -c` должен сказать `install-macos.sh: OK`.
3. Прочитайте скрипт. Это обычный текст, у каждого шага есть комментарий.
4. Посмотрите план, ничего не меняя: `bash install-macos.sh --dry-run`
5. Запустите по-настоящему: `bash install-macos.sh`

## Что он делает, шаг за шагом

1. **Проверяет Mac**: версию macOS, процессор, свободное место, связь с GitHub, nodejs.org и реестром npm, и что
   NodeWise Studio не запущено.
2. **Загружает исходный код** последнего выпуска с GitHub архивом (Git не нужен) в отдельную папку сборки
   `~/Library/Caches/nodewise-studio-installer` и проверяет, что это именно этот проект: имя папки в архиве, имена и
   версию в его `package.json`.
3. **Node.js для сборки.** Если Node.js нужной проекту версии (22) уже есть на Mac (с nodejs.org, из Homebrew, nvm
   или fnm), берётся он. Иначе отдельная копия скачивается с nodejs.org в папку сборки и сверяется с
   `SHASUMS256.txt` с nodejs.org. Homebrew не нужен, ваш собственный Node.js не меняется.
4. **Собирает приложение**: `npm ci`, `npm run build`, затем Electron Forge делает `NodeWise Studio.app`. Модуль базы
   данных для Mac на Apple silicon и на Intel есть готовый, поэтому Command Line Tools от Apple не нужны. Этот шаг
   самый долгий.
5. **Устанавливает** в `~/Applications/NodeWise Studio.app` (папка создаётся, если её нет): новая копия готовится
   рядом со старой, подписывается для этого Mac (см. ниже) и затем подменяет её, поэтому при сбое старая версия
   продолжает работать.
6. **Проверяет установленное приложение**: оно должно напечатать версию по `--version`, открыть окно с временным
   профилем и не запуститься второй раз. Папку ваших данных и связку ключей эта проверка не трогает.

В конце скрипт пишет, где приложение, где ваши данные, как запустить и удалить приложение и где журнал.

## Сколько это длится

Больше всего времени уходит на загрузку пакетов и сборку: примерно 5–15 минут при обычной связи. Пока скрипт
работает, ваше участие не нужно.

## О чём он спрашивает

Обычно ни о чём. Он спрашивает один раз, прежде чем что-то ставить для всего Mac, только если вы сами это выбрали
(`--system-node`) или если в будущей версии не окажется готового модуля базы данных для вашего Mac (тогда он
предложит Command Line Tools от Apple: откроется системное окно, и скрипт подождёт окончания установки). `--yes`
отвечает на эти вопросы «да». Ваши данные никогда не удаляются без вашего явного ответа.

## Параметры

| Параметр | Что делает |
|---|---|
| `--version v1.0.0` | Собирает этот выпуск вместо последнего. |
| `--main` | Собирает самый новый код ветки main (не выпуск; может быть сломан). |
| `--source <папка>` | Собирает из папки, где уже лежит исходный код. |
| `--system-applications` | Ставит в `/Applications` вместо `~/Applications`. |
| `--system-node` | Ставит Node.js для всего Mac официальным установщиком (спросит пароль). |
| `--private-node` | Берёт отдельную копию Node.js, даже если подходящий уже установлен. |
| `--dry-run` | Печатает каждый шаг и ничего не меняет. |
| `--keep-build` | Оставляет папку сборки (около 1,5 ГБ) после установки. |
| `--build-dir <папка>` | Собирает в другом месте. |
| `--log <файл>` | Пишет журнал туда вместо `~/Library/Logs/nodewise-studio-install.log`. |
| `--lang en` или `ru` | Язык сообщений; по умолчанию язык Mac. |
| `--uninstall`, `--purge-data` | См. «Удаление» ниже. |
| `--help` | Показывает параметры и коды выхода. |

## Обновление

Запустите ту же команду ещё раз. Скрипт соберёт последний выпуск и заменит приложение на месте. Настройки, ключи,
проекты и разговоры сохранятся: они лежат в отдельной папке. Сначала закройте приложение, иначе скрипт остановится и
скажет об этом.

После обновления macOS может один раз спросить, можно ли NodeWise Studio пользоваться «nodewise-studio Safe Storage» в
связке ключей: каждая сборка заново подписывается на вашем Mac, и связка ключей видит новую программу. Введите пароль
от учётной записи и выберите «Разрешать всегда». Так должно быть по тому, как связка ключей обращается с такими
подписями; на настоящем Mac это пока не проверено.

## Удаление

```bash
bash ~/Library/Application\ Support/nodewise-studio-installer/install-macos.sh --uninstall
```

Скрипт удаляет приложение, свою папку и папку сборки. Затем спрашивает, удалить ли и ваши данные; ответ «нет», если
вы не введёте `д`. `--purge-data` удаляет данные без вопроса, вместе с записью в связке ключей и файлом настроек
приложения. См. [Удаление](Removing.ru.md).

## Где ваши данные

`~/Library/Application Support/nodewise-studio`. Ключи шифруются ключом, который macOS хранит в вашей связке ключей
под именем «nodewise-studio Safe Storage». [Папка с данными](../reference/Data-Folder.ru.md)

## Почему приложение не подписано и что скажет macOS

Чтобы подписать и заверить приложение для Mac, нужно платное членство в программе разработчиков Apple, которого у
проекта пока нет. Поэтому скрипт подписывает приложение «ad hoc» на вашем Mac (`codesign --sign -`): такая подпись не
называет издателя, она только позволяет Mac на Apple silicon выполнять код и даёт macOS заметить, если файлы потом
изменятся. Gatekeeper проверяет приложения с пометкой «скачано из интернета»; у приложения, собранного на вашем Mac,
её нет (скрипт ещё и снимает её), поэтому предупреждения «не удаётся открыть» быть не должно. На настоящем Mac ничего из
этого пока не видели.

## Если что-то пошло не так

Скрипт завершается с кодом выхода и сообщением и печатает путь к журналу (по умолчанию
`~/Library/Logs/nodewise-studio-install.log`). В журнале каждая команда и её вывод; приложите его, когда сообщаете о
проблеме.

| Код | Что значит | Что делать |
|---|---|---|
| 0 | Готово. | Ничего. |
| 1 | Что-то неожиданно сломалось. | Посмотрите последние строки, которые напечатал скрипт; сообщите о проблеме, приложив журнал. |
| 2 | Неверный параметр или два параметра, которые друг друга исключают. | См. `--help`. |
| 3 | Система не поддерживается: не macOS, старее 13, неизвестный процессор или запуск через `sudo`. | Нужен поддерживаемый Mac; запускайте без `sudo`. |
| 4 | Не хватает свободного места. | Освободите место или соберите в другом месте: `--build-dir`. |
| 5 | Нет связи с GitHub, nodejs.org или реестром npm. | Проверьте подключение; если задан `https_proxy`, используется прокси. |
| 6 | Нужного инструмента нет, и он не установлен (вы ответили «нет»). | Запустите снова и согласитесь. |
| 7 | Не удалась загрузка или проверка: архив не от этого проекта, не совпала контрольная сумма или подпись, или GitHub не назвал последний выпуск. | Запустите снова; укажите выпуск: `--version v1.0.0`. |
| 8 | Сборка не удалась. | В журнале видна команда, на которой остановилось. |
| 9 | Не удался шаг установки; старая версия не тронута. | Посмотрите журнал; для `/Applications` проверьте, что вам можно туда писать. |
| 10 | Установленное приложение не прошло проверку. | Сообщите о проблеме, приложив журнал. |
| 11 | NodeWise Studio запущено. | Закройте его и запустите скрипт снова. |
| 12 | Отменено клавишами Ctrl+C. | Запустите снова, когда будете готовы. |
| 13 | Этот выпуск скриптом не установить: он вышел раньше, чем появился скрипт. | Возьмите более новый выпуск: `--version`. |

## Что ещё не проверено

Весь скрипт. Он появился в 1.0.0 и на настоящем Mac не проверялся. Проверка на машинах GitHub с macOS (Apple
silicon и Intel, с тем bash 3.2, что есть в macOS) есть и ещё доводится до успешного прохода. Особенно интересны: сама
macOS 13, прокси, `--system-node`, `--system-applications`, Mac, которому нужны Command Line Tools, и вопрос связки
ключей после обновления. Сообщите, пожалуйста, что получилось, в обращениях (Issues) проекта, приложив журнал
(`~/Library/Logs/nodewise-studio-install.log`) и версию macOS (меню Apple ▸ Об этом Mac).
