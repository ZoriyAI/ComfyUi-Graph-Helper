# Установка на Windows

Готового пакета для Windows пока нет. Вместо него в каждом выпуске есть скрипт `install-windows.ps1`: он собирает
приложение на вашем компьютере из исходного кода проекта и устанавливает его для вас. Всё делает одна команда; на
этой странице сказано, что она делает, о чём спрашивает и как всё отменить.

## Что нужно

- Windows 10 22H2 или Windows 11, 64-битный x86 (x64). Windows на ARM пока не поддерживается.
- Windows PowerShell 5.1 (есть в Windows) или PowerShell 7.
- Около 3,5 ГБ свободного места для сборки (в конце она удаляется) и 600 МБ для приложения.
- Доступ в интернет к `github.com`, `nodejs.org` и `registry.npmjs.org`.
- Права администратора не нужны. Не открывайте PowerShell «от имени администратора»: приложение ставится для вашего
  пользователя.

## Одна команда

Откройте **PowerShell** (меню «Пуск», наберите «PowerShell») и вставьте две строки:

```powershell
Invoke-WebRequest -UseBasicParsing <адрес проекта>/releases/latest/download/install-windows.ps1 -OutFile install-windows.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\install-windows.ps1
```

На главной странице проекта (README) те же строки показаны с настоящим адресом.

`-ExecutionPolicy Bypass` разрешает запустить скачанный скрипт только этому процессу PowerShell. Настройки Windows
не меняются: в следующем окне PowerShell правила те же, что были.

## Осторожный способ

1. Скачайте `install-windows.ps1` и `SHA256SUMS` со страницы выпуска.
2. Проверьте файл: `Get-FileHash .\install-windows.ps1 -Algorithm SHA256` должен напечатать то же значение (заглавными
   буквами), что и строка для `install-windows.ps1` в `SHA256SUMS`.
3. Прочитайте скрипт. Это обычный текст, у каждого шага есть комментарий.
4. Посмотрите план, ничего не меняя:
   `powershell -NoProfile -ExecutionPolicy Bypass -File .\install-windows.ps1 -DryRun`
5. Запустите по-настоящему, без `-DryRun`.

## Что он делает, шаг за шагом

1. **Проверяет компьютер**: версию Windows, процессор, PowerShell, свободное место, связь с GitHub, nodejs.org и
   реестром npm, и что NodeWise Studio не запущено.
2. **Загружает исходный код** последнего выпуска с GitHub архивом zip (Git не нужен) в отдельную папку сборки
   `%LOCALAPPDATA%\nodewise-studio-installer` и проверяет, что это именно этот проект: имя папки в архиве, имена и
   версию в его `package.json`.
3. **Node.js для сборки.** Если Node.js нужной проекту версии (22) уже установлен, берётся он. Иначе отдельная копия
   скачивается с nodejs.org в папку сборки и сверяется с `SHASUMS256.txt` с nodejs.org. Ваш собственный Node.js любой
   версии не меняется.
4. **Собирает приложение**: `npm ci`, `npm run build`, затем Electron Forge делает папку приложения. Модуль базы данных
   для Windows x64 есть готовый, поэтому компилятор не нужен. Этот шаг самый долгий.
5. **Устанавливает** в `%LOCALAPPDATA%\Programs\NodeWise Studio`: новая копия готовится рядом со старой и затем
   подменяет её, поэтому при сбое старая версия продолжает работать. Добавляет ярлык в меню «Пуск» и строку в
   Параметры ▸ Приложения ▸ Установленные приложения.
6. **Проверяет установленное приложение**: оно должно напечатать версию по `--version`, открыть окно с временным
   профилем и не запуститься второй раз. Папку ваших данных эта проверка не трогает.

В конце скрипт пишет, где приложение, где ваши данные, как запустить и удалить приложение и где журнал.

## Сколько это длится

Больше всего времени уходит на загрузку пакетов и сборку: примерно 5–15 минут при обычной связи. Пока скрипт
работает, ваше участие не нужно.

## О чём он спрашивает

Обычно ни о чём. Он спрашивает один раз, прежде чем что-то ставить для всего компьютера, только если вы сами это
выбрали (`-SystemNode`) или если в будущей версии не окажется готового модуля базы данных для вашей системы (тогда
нужны инструменты сборки C++ из Visual Studio и Python). `-Yes` отвечает на эти вопросы «да». Ваши данные никогда не
удаляются без вашего явного ответа.

## Параметры

| Параметр | Что делает |
|---|---|
| `-Version v1.0.0` | Собирает этот выпуск вместо последнего. |
| `-Main` | Собирает самый новый код ветки main (не выпуск; может быть сломан). |
| `-Source <папка>` | Собирает из папки, где уже лежит исходный код. |
| `-DesktopShortcut` | Кладёт ярлык и на рабочий стол. |
| `-SystemNode` | Ставит Node.js для всего компьютера через winget вместо отдельной копии. |
| `-PrivateNode` | Берёт отдельную копию Node.js, даже если подходящий уже установлен. |
| `-DryRun` | Печатает каждый шаг и ничего не меняет. |
| `-KeepBuild` | Оставляет папку сборки (около 1,5 ГБ) после установки. |
| `-BuildDir <папка>` | Собирает в другом месте, например на другом диске. |
| `-LogPath <файл>` | Пишет журнал туда вместо `%TEMP%\nodewise-studio-install.log`. |
| `-Language en` или `ru` | Язык сообщений; по умолчанию язык Windows. |
| `-Uninstall`, `-PurgeData` | См. «Удаление» ниже. |
| `-Help` | Показывает параметры и коды выхода. |

## Обновление

Запустите ту же команду ещё раз. Скрипт соберёт последний выпуск и заменит приложение на месте. Настройки, ключи,
проекты и разговоры сохранятся: они лежат в отдельной папке. Сначала закройте приложение, иначе скрипт остановится и
скажет об этом.

## Удаление

Параметры ▸ Приложения ▸ Установленные приложения ▸ NodeWise Studio ▸ Удалить. Или в PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:LOCALAPPDATA\Programs\NodeWise Studio\install-windows.ps1" -Uninstall
```

Скрипт удаляет папку приложения, ярлыки, строку в «Установленных приложениях» и папку сборки. Затем спрашивает,
удалить ли и ваши данные; ответ «нет», если вы не введёте `д`. `-PurgeData` удаляет данные без вопроса. См.
[Удаление](Removing.ru.md).

## Где ваши данные

`%APPDATA%\nodewise-studio`, например `C:\Users\you\AppData\Roaming\nodewise-studio`. Ключи шифрует Windows (DPAPI) для
вашего пользователя. [Папка с данными](../reference/Data-Folder.ru.md)

## Почему приложение не подписано и что скажет Windows

Чтобы подписать программу для Windows, нужен платный сертификат, которого у проекта пока нет. Готовая программа не
скачивается: приложение собирается на вашем компьютере. SmartScreen проверяет файлы с пометкой «скачано из
интернета»; у файлов, которые собирает скрипт, такой пометки нет, поэтому при запуске приложения SmartScreen ничего
спрашивать не должен. Автоматические сборки проекта записывают, есть ли такая пометка у какого-нибудь установленного
файла; на настоящем компьютере это пока не проверено.

## Если что-то пошло не так

Скрипт завершается с кодом выхода и сообщением и печатает путь к журналу (по умолчанию
`%TEMP%\nodewise-studio-install.log`). В журнале каждая команда и её вывод; приложите его, когда сообщаете о проблеме.

| Код | Что значит | Что делать |
|---|---|---|
| 0 | Готово. | Ничего. |
| 1 | Что-то неожиданно сломалось. | Посмотрите последние строки журнала; сообщите о проблеме, приложив журнал. |
| 2 | Неверный параметр или два параметра, которые друг друга исключают. | См. `-Help`. |
| 3 | Система не поддерживается: не Windows, старее 22H2, не x64 или старый PowerShell. | Нужна поддерживаемая система; на Linux поставьте пакет. |
| 4 | Не хватает свободного места. | Освободите место или соберите в другом месте: `-BuildDir D:\build`. |
| 5 | Нет связи с GitHub, nodejs.org или реестром npm. | Проверьте подключение; если задан `HTTPS_PROXY`, используется прокси. |
| 6 | Нужного инструмента нет, и он не установлен (вы ответили «нет» или нет winget). | Запустите снова и согласитесь или поставьте «Установщик приложений» из Microsoft Store. |
| 7 | Не удалась загрузка или проверка: архив не от этого проекта, не совпала контрольная сумма или подпись, или GitHub не назвал последний выпуск. | Запустите снова; укажите выпуск: `-Version v1.0.0`. |
| 8 | Сборка не удалась. | В журнале видна команда, на которой остановилось; длинные пути к папкам могут мешать: попробуйте `-BuildDir C:\nwbuild`. |
| 9 | Не удался шаг установки; старая версия не тронута. | Посмотрите журнал; проверьте, что никто не держит файлы в папке приложения. |
| 10 | Установленное приложение не прошло проверку. | Сообщите о проблеме, приложив журнал. |
| 11 | NodeWise Studio запущено. | Закройте его и запустите скрипт снова. |
| 12 | Отменено (этот код у скрипта для macOS; на Ctrl+C PowerShell сам завершает скрипт). | Запустите снова, когда будете готовы. |
| 13 | Этот выпуск скриптом не установить: он вышел раньше, чем появился скрипт. | Возьмите более новый выпуск: `-Version`. |

## Что ещё не проверено

Автоматические сборки проекта запускают этот скрипт на машинах GitHub с Windows (Windows Server 2022 и самый новый
образ Windows Server, с Windows PowerShell 5.1 и PowerShell 7). На разных настоящих компьютерах он ещё не проверен:
Windows 10 и 11 на обычных ПК, имя пользователя не латиницей, прокси, `-SystemNode` с winget и компьютер, которому
нужны инструменты сборки C++. Если что-то не получится, сообщите о проблеме и приложите журнал.
