## Подтверждённые проблемы main, уже затронутые PR #22

### P1. Новый проект создаётся в формате, запрещающем создание subgraph

Доказательство: [actions.ts:141–142](https://github.com/ZoriyAI/ComfyUi-Graph-Helper/blob/0bf6c06219b5395d88a5dcd283e1deb254471b49/src/renderer/commands/actions.ts#L141) задаёт EMPTY_WORKFLOW version 0.4; [graphOps.ts:109–110](https://github.com/ZoriyAI/ComfyUi-Graph-Helper/blob/0bf6c06219b5395d88a5dcd283e1deb254471b49/src/main/commands/graphOps.ts#L109) отклоняет subgraph для 0.4.

Сценарий: File → New → добавить две ноды → выделить → Create subgraph. Получится отказ «Subgraphs need workflow format 1», хотя это штатный новый проект.

Предлагаемое исправление PR #22: новый проект в format1. Приёмка: сценарий выше, сохранение native project, export и повторное открытие. Существующий тест экспорта «с нуля» в workflowRoundTrip проверяет document=null, а не File→New с явным 0.4.

### P1. Проверка графа не обнаруживает существенные классы структурных ошибок

[check.ts:240–281](https://github.com/ZoriyAI/ComfyUi-Graph-Helper/blob/0bf6c06219b5395d88a5dcd283e1deb254471b49/src/main/knowledge/check.ts#L240) берёт только root nodes/edges для type/required-input/base-family/unset проверок. Нет обхода snapshot.subgraphs для этих проверок; нет циклов, отсутствующих endpoints/handles и проверки widget type/range/COMBO values. [commit.ts:546–585](https://github.com/ZoriyAI/ComfyUi-Graph-Helper/blob/0bf6c06219b5395d88a5dcd283e1deb254471b49/src/main/commands/commit.ts#L546) при connect сверяет порты и типы, но не цикл.

Сценарии: два известных wildcard-совместимых узла соединить по кругу; импортировать связь на отсутствующий endpoint/handle; поместить KSampler с steps=-1 или строкой вместо INT; внутри subgraph оставить обязательный порт несоединённым. В main нет соответствующего пути проверки. Для изолированного сценария без прочих находок report.ok может оставаться true.

Уточнение: missing node/model по raw definitions частично учитываются через missingDeps/missingOnGraph; нельзя писать «внутренности подграфов вообще не проверяются». Пробел именно в остальных перечисленных проверках.

PR #22 добавляет graphlib, циклы, structural checks, field checks и проверки внутренних уровней. Новые тесты: graphValidation.test.ts. Приёмка требует отдельно проверить backend, renderer и AI tools; один UI guard недостаточен.

### P1. Открытие/импорт заменяет текущую работу без общего предупреждения

[actions.ts:47–65](https://github.com/ZoriyAI/ComfyUi-Graph-Helper/blob/0bf6c06219b5395d88a5dcd283e1deb254471b49/src/renderer/commands/actions.ts#L47) и [118–128](https://github.com/ZoriyAI/ComfyUi-Graph-Helper/blob/0bf6c06219b5395d88a5dcd283e1deb254471b49/src/renderer/commands/actions.ts#L118) сразу открывают диалоги и применяют проекции; dirty-guard есть только у New в 149–158.

Сценарий: изменить несохранённый граф → File→Import или Open → выбрать другой файл. Текущая работа заменяется без такого же предупреждения, как New. Предыдущий снимок остаётся в истории: это риск незаметной замены, а не утверждение о необратимой потере.

PR #22 вводит requestReplacement и replacementGuard.test.ts. Приёмка: отмена подтверждения, отмена file picker после подтверждения, Open и Import, первый импорт в пустой граф, открытая AI-сессия.

### P2. Групповое движение/удаление создаёт много ревизий

[actions.ts:195–201](https://github.com/ZoriyAI/ComfyUi-Graph-Helper/blob/0bf6c06219b5395d88a5dcd283e1deb254471b49/src/renderer/commands/actions.ts#L195) коммитит remove-node по одной ноде; [CanvasFlow.tsx:330–355](https://github.com/ZoriyAI/ComfyUi-Graph-Helper/blob/0bf6c06219b5395d88a5dcd283e1deb254471b49/src/renderer/components/graph/CanvasFlow.tsx#L330) коммитит каждую завершённую позицию отдельно. Стандартный move-nodes уже существует в engine, но этот drag-путь его не использует.

Сценарий: выделить 10 нод, передвинуть/удалить, нажать Undo один раз. Возвращается один шаг/часть операции; снимков и записей столько, сколько отдельных команд.

PR #22 предлагает атомарные операции выделения, clipboard, групповые движения. Приёмка: один gesture — одна ревизия — один undo, в root и внутри subgraph, включая инцидентные и отдельно выделенные рёбра.

### P1/P2. Очистка истории не защищает реальные открытые предложения

[history.ts:55–58](https://github.com/ZoriyAI/ComfyUi-Graph-Helper/blob/0bf6c06219b5395d88a5dcd283e1deb254471b49/src/main/commands/history.ts#L55) ищет status='open', а [proposals/repository.ts:46–61](https://github.com/ZoriyAI/ComfyUi-Graph-Helper/blob/0bf6c06219b5395d88a5dcd283e1deb254471b49/src/main/proposals/repository.ts#L46) создаёт status='proposed'.

Сценарий: создать предложение, выполнить достаточно правок для выхода его исходной ревизии за окно истории, дождаться prune. Ревизия предложения не попадает в protected set. [staleReason:85–104](https://github.com/ZoriyAI/ComfyUi-Graph-Helper/blob/0bf6c06219b5395d88a5dcd283e1deb254471b49/src/main/proposals/repository.ts#L85) теряет исходное состояние и при loadRevision=null возвращает null.

Пробел существующего теста: [historyLimit.test.ts:86–99](https://github.com/ZoriyAI/ComfyUi-Graph-Helper/blob/0bf6c06219b5395d88a5dcd283e1deb254471b49/tests/unit/historyLimit.test.ts#L86) напрямую вставляет вымышленный status='open', не вызывает createProposal, поэтому не воспроизводит runtime-состояние.

PR #22 меняет условие на IN ('proposed','open') и добавляет тест с настоящим createProposal.

## Выводы вне PR #22 и важные ограничения

### P1/P2: поведение Undo AI-сессии затрагивает ручные правки

Это подтверждённое и намеренно протестированное UX-решение, а не неустановленный баг: [undoState.ts:76–90](https://github.com/ZoriyAI/ComfyUi-Graph-Helper/blob/0bf6c06219b5395d88a5dcd283e1deb254471b49/src/renderer/state/undoState.ts#L76) откатывает до снимка перед первым AI шагом. [undoRedo.test.ts:150–164](https://github.com/ZoriyAI/ComfyUi-Graph-Helper/blob/0bf6c06219b5395d88a5dcd283e1deb254471b49/tests/unit/undoRedo.test.ts#L150) явно задаёт AI r4 → ручное перемещение r5 → AI r6/r7 → Undo к r3. Ручное перемещение тоже исчезает.

Рекомендация: определить понятную семантику. Либо показывать, что отменится весь интервал с N ручными правками, либо разбивать run при ручном действии, либо реализовывать выборочную отмену, сохраняя независимые ручные изменения. Не менять без осмысленного продуктового решения.

### Совместимость с живым ComfyUI пока не доказана всеми тестами

[codec.ts:1015–1027](https://github.com/ZoriyAI/ComfyUi-Graph-Helper/blob/0bf6c06219b5395d88a5dcd283e1deb254471b49/src/shared/workflow/codec.ts#L1015) прямо оговаривает: subgraph schema assumptions не проверены тестами с running frontend; доказан собственный import→edit→export. [tests/corpus/workflowRoundTrip.test.ts:13–14](https://github.com/ZoriyAI/ComfyUi-Graph-Helper/blob/0bf6c06219b5395d88a5dcd283e1deb254471b49/tests/corpus/workflowRoundTrip.test.ts#L13), а также 244 и 323: корпусные suite skipped без WORKFLOW_CORPUS.

Рекомендация: отдельный compatibility gate — экспорт из Helper → загрузка официальным ComfyUI frontend → повторное сохранение → семантическое сравнение. Без генерации. Корпус пользователя: реальные Wan/Flux/video workflows, frontend-only nodes, native nested subgraphs, promoted widgets, неизвестные custom ноды, обновлённый/устаревший object_info. Фиксировать точные upstream версии и размер/происхождение корпуса.

### История имеет мягкий, а не жёсткий бюджет 256 MiB

[history.ts:18–30](https://github.com/ZoriyAI/ComfyUi-Graph-Helper/blob/0bf6c06219b5395d88a5dcd283e1deb254471b49/src/main/commands/history.ts#L18) оставляет минимум 200 полных снимков. Для снимка 10 MiB это около 2 GiB только graph revisions; защищённые ревизии добавляются сверху. [commit.ts:751–770](https://github.com/ZoriyAI/ComfyUi-Graph-Helper/blob/0bf6c06219b5395d88a5dcd283e1deb254471b49/src/main/commands/commit.ts#L751) сериализует весь граф на каждый коммит.

Не считать это измеренным performance-дефектом. Нужны замеры UI latency, времени commit и роста SQLite на пользовательских тяжёлых workflow; решать min history vs hard disk budget по результатам.

### Уведомление об исключениях ручных коммитов неполное

[commit.ts renderer:67–78](https://github.com/ZoriyAI/ComfyUi-Graph-Helper/blob/0bf6c06219b5395d88a5dcd283e1deb254471b49/src/renderer/components/graph/commit.ts#L67) показывает toast для rejected/conflict, но Promise rejection превращает в null через catch. Storage errors main специально нормализует в rejected; другие непредвиденные IPC/engine исключения могут выглядеть как безрезультатная операция.

Рекомендация: единый видимый текст для транспортного/непредвиденного сбоя с сохранением диагностики, отдельно от ожидаемого отказа. Приёмка: отвергнутый Promise в submitManual не должен завершаться без пользовательского сообщения.

### Нативные внутренние группы и boundary positions показаны ограниченно

[GroupLayer.tsx:95–100](https://github.com/ZoriyAI/ComfyUi-Graph-Helper/blob/0bf6c06219b5395d88a5dcd283e1deb254471b49/src/renderer/components/graph/layers/GroupLayer.tsx#L95) скрывает группы в definition view. [CanvasFlow.tsx:334–344](https://github.com/ZoriyAI/ComfyUi-Graph-Helper/blob/0bf6c06219b5395d88a5dcd283e1deb254471b49/src/renderer/components/graph/CanvasFlow.tsx#L334) оставляет перемещение boundary pseudo-nodes только в отображении, не сохраняет. Это ограничения полноты редактора; их нужно явно описать, если обещается соответствие импортированному файлу.

## Сильные стороны, которые следует сохранить

- Неизвестные native поля и неизвестные ноды не выбрасываются лишь из-за отсутствия каталога; есть tests/unit/workflowCodec.test.ts:80, workflowRoundTrip.test.ts:56–71, subgraphCodec.test.ts:47–93.
- Native project сохраняет модель графа, subgraphs, groups, extensions; ComfyUI export удаляет только namespace приложения.
- Счётчики node/link IDs монотонны, включая undo; перенос конфликтующих ID при dissolve предусмотрен.
- Если widget order неизвестен, параметры не раскладываются наугад: codec.ts:591–612; при импортированных widgets_values сохраняется native представление.
- Подключение к занятым входам заменяет прежнюю связь; typed port guards есть и в engine.
- Команды AI/manual проходят одну SQLite транзакцию; retry action-id идемпотентен, expected revision предотвращает слепое применение устаревшего шага.

## Дополнительные гипотезы для проверки, не выдавать за доказанный дефект нативного workflow

1. Dissolve promoted widget может потерять значение instance для позиционного inner widgets_values без inner.widgets names: graphOps.ts:441–465 использует только raw inner.widgets для индекса, не catalog.widgetOrder. Импортёр такой документ принимает. Минимальная форма: внутренний текст widgets_values=['old'], отсутствие widgets, instance properties.proxyWidgets=[['1','text']], instance widgets_values=['new']; после dissolve алгоритм не находит слот и сохраняет old. Нужно проверить, действительно ли актуальный ComfyUI сохраняет эту форму и что означает pair с nodeId != '-1'. Без этого называть доказанным runtime-дефектом ComfyUI некорректно.
2. Переименование promoted input через label может нарушить UI-сопоставление порта по исходному name в EditorNodes.tsx:277, потому что instancePorts использует slotLabel, а promoted input ищется по field.name. Требуется fixture из живого frontend и E2E тест.
3. Muted/bypassed nodes при проверке обязательных входов: check.ts не фильтрует mode. Нужны сценарии с реальным execution semantics, иначе нельзя утверждать false positive.

**Триггер, детерминируемый задержкой fake fetch.** Запустить direct sync, дать завершиться object_info, задержать ответ `/customnode/installed` или последней model folder. Поменять адрес в Settings (auto sync off), затем вернуть задержанный ответ.

**Условие риска.** Секрет должен попасть в catalog description, model metadata/notes или обычный graph value нераспознанного формата. Например, сервер случайно отразил manual MCP token в description. Сохранять формы JSON/types; apply recursive redaction перед передачей SDK.

## Уточнение по удалению секретов

Root отдельно обнаружил backup retention: pre-migration .bak содержит копию SQLite вместе с encrypted secret_records, а Forget All очищает текущую БД/файлы ключей/память. ## Подтверждённые проблемы и ограничения

### L1. Уроки могут принять неправильный комплект моделей; автоматический выбор «другого» файла не проверяет назначение

### L2. UI не передаёт триггеры WanVideoLoraSelect в урок Wrapper

Приоритет: высокий. Урок `wrapper` на шаге `trigger` требует слова выбранной `WanVideoLoraSelect.lora`. ### L3. Факты LoRA кэшируются навсегда по одному имени файла

Приоритет: средний. Модульный `triggerCache` хранит [] и после ошибки/отсутствия метаданных; успешный ответ повторно не запрашивается, если имя файла не сменилось. Эффект зависит только от списка файлов, а не от sync/catalog identity. При последующем обогащении LoRA или подключении другого ComfyUI с тем же именем урок продолжит старые слова либо отсутствие слов до перезапуска страницы.

Источник: [lessonModel.ts:120-147](https://github.com/ZoriyAI/ComfyUi-Graph-Helper/blob/0bf6c06219b5395d88a5dcd283e1deb254471b49/src/renderer/components/lessons/lessonModel.ts#L120). Для сравнения, сведения классов нод уже умеют обновляться после синхронизации: [nodeInfo.ts:39](https://github.com/ZoriyAI/ComfyUi-Graph-Helper/blob/0bf6c06219b5395d88a5dcd283e1deb254471b49/src/renderer/components/graph/nodeInfo.ts#L39).

Рекомендация: версионировать cache snapshot identity/lastSyncAt и модельными обновлениями; различать not-loaded/error/no-trigger-words, повторять чтение после обновления или временной ошибки. Добавить UI-тест «открыть урок до чтения metadata → metadata появились → правило стало проверяться».

### L4. «Проблем не найдено» означает ограниченную статическую проверку, а не гарантию принимаемого ComfyUI графа

Приоритет: высокий для точности обещаний/документации. `baseModelMismatches` проверяет связи LoRA с базовыми загрузчиками. Неправильные VAE/text encoder пары вообще без LoRA этот метод не проверяет. Неизвестное семейство считается совместимым, чтобы избегать ложных ошибок. Это разумное поведение, но ему нужна явная неизвестность. Руководство сейчас говорит, что чистый итог значит «ComfyUI должен принять граф», и в подсказке о семействах перечисляет LoRA/VAE/checkpoint, что шире кода.

Источники: [check.ts:151](https://github.com/ZoriyAI/ComfyUi-Graph-Helper/blob/0bf6c06219b5395d88a5dcd283e1deb254471b49/src/main/knowledge/check.ts#L151), [check.ts:268](https://github.com/ZoriyAI/ComfyUi-Graph-Helper/blob/0bf6c06219b5395d88a5dcd283e1deb254471b49/src/main/knowledge/check.ts#L268), [baseModel.ts:198](https://github.com/ZoriyAI/ComfyUi-Graph-Helper/blob/0bf6c06219b5395d88a5dcd283e1deb254471b49/src/shared/knowledge/baseModel.ts#L198), [Checking-A-Graph.ru.md:13](https://github.com/ZoriyAI/ComfyUi-Graph-Helper/blob/0bf6c06219b5395d88a5dcd283e1deb254471b49/docs/wiki/graph/Checking-A-Graph.ru.md#L13), [строка 24](https://github.com/ZoriyAI/ComfyUi-Graph-Helper/blob/0bf6c06219b5395d88a5dcd283e1deb254471b49/docs/wiki/graph/Checking-A-Graph.ru.md#L24).

### L5. Существующая учебная структура пока не представлена в списке уроков

Приоритет: средний, продуктовая рекомендация. Данные `LESSON_PATH` уже задают группы и follows, но LessonPanel строит плоский `LESSONS.map`; в карточке выводится лишь первый элемент LESSON_AFTER. - Производительность на больших импортированных графах: список вычисляет lessonProgress для каждого урока, движок допускает до 200 000 попыток поиска соответствий; это ограничивает бесконечный поиск, но само по себе не доказывает отзывчивость UI. Нужны бенчмарки на 100/500/1000 нодах и многих одинаковых текстовых/самплерных нодах. ## Порядок будущих улучшений

1. Сначала точность статусов и требований: файл/семейство/назначение, неизвестность, устранение автоматического случайного выбора модели (L1/L4).
2. Затем факты LoRA: единый adapter для обычных нод и Wrapper, обновляемый cache, E2E UI→каталог→проверка (L2/L3).
3. Проверочные реальные object_info snapshots и несовместимые комплекты моделей для уроков; отдельно проверять собственный пример, чужой импорт и обновившийся пак. Сохранить offline/fake тесты как быстрый слой.
4. Учебная навигация на основе уже имеющегося LESSON_PATH, явные критерии завершения и причины чисел; не наращивать ещё десятки уроков до исправления точности.
5. После этого измерить большие графы и профили ComfyUI пользователя; только после измерений выбирать оптимизацию. Внешний ComfyUI и GPU не трогать в рамках нынешнего исследования.

## Критерии приёмки будущих изменений

| Изменение | Проверяемый результат |
|---|---|
| L1: выбор моделей | Для каталога `[wan_high, flux_dev, wan_low]` шаг high/low принимает только допустимую пару; другое семейство или второй high не считаются готовым low. При неизвестном назначении выводится неизвестность/ручной выбор. |
| L1: автоматическое исправление | «Сделать за меня» не выбирает просто первый другой файл; если нет проверенного low-кандидата, действие не подменяет его случайным файлом. |
| L2: триггеры Wrapper | Реальный UI с WanVideoLoraSelect.lora и каталогом triggerWords=['neon rain'] останавливается на trigger без этих слов и пропускает шаг после добавления допустимого trigger. |
| L3: cache | После первоначального ответа без метаданных и следующего успешного чтения/обогащения слова появляются в проверке без перезапуска; смена сервера с одинаковым именем файла не сохраняет чужие факты. |
| L4: границы проверки | Отчёт различает «не найдено ошибок по этому каталогу» и непроверенные условия; несовместимые VAE/CLIP не объявляются доказанно совместимыми только из-за отсутствия LoRA. |
| L5: учебный путь | Пользователь находит базовые модели, видео и anchor-picture по группам, видит доступность по своему каталогу и следующий рекомендуемый урок, сохраняя свободный переход. |
| Проверка содержимого | Для выбранных поддерживаемых версий ComfyUI/паков есть сохранённые реальные schemas/examples с SHA/версиями; тесты сравнивают уроки с ними и проверяют ошибочные сценарии, а не только собственный fake. |

Точность самих инструкций о новых моделях и узлах здесь проверена на внутреннюю согласованность с кодом/тестами, а не полностью на актуальную upstream реализацию ComfyUI и каждого custom node pack. Утверждения о GPU-памяти/времени генерации, всех портах последних паков и стабильности личности в результатах нуждаются в отдельной проверке на выбранных версиях. Нельзя представлять эту заметку как полный аудит научной/практической точности всех 45 уроков.

Работа по коду/исполнению остаётся не начатой: пользователь отдельно определит момент реализации.
