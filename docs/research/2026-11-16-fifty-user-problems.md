# 50 задач и затруднений: от установки до собственного результата

Дата исследования: 2026-11-16. Требование владельца: низкий порог входа для человека без технической подготовки; решение практической задачи сразу после установки. Вход в продукт — «что хочу получить / что не получается», затем понятные шаги и визуальное объяснение. Не требовать знания названий нод, портов, служб или написания запроса агенту.

Это 50 отдельных сценариев из официальной документации и сообщений пользователей в репозитории ComfyUI, а не рейтинг частоты и не утверждение о 50 ошибках NodeWise. Исходный список зафиксирован до реализации новых мастеров. Обсуждения подтверждают существование затруднения в указанной версии; актуальный статус конкретного upstream-багa может измениться. Решения ниже — проектное предложение NodeWise на основе источников.

Обозначения: **есть** — соответствующий механизм найден в исходниках, но это не новая функциональная приёмка; **добавить** — маршрут помощи/проверку надо реализовать; **внешнее** — действие выполняется в ComfyUI/его окружении, NodeWise объясняет и ведёт к нему, не обещает исправить автоматически. Генерация медиа происходит в ComfyUI; успешная проверка структуры не гарантирует результат или достаточную память.

## Что реализовать по этому списку

1. Единый мастер «Решить проблему»: поиск человеческими словами и по тексту ошибки; категории; три шага «понять → проверить → действовать»; видимая кнопка назад/закрыть; работа без агента.
2. На каждом шаге показывать ожидаемый наблюдаемый результат. «Я проверил» — отметка человека, не автоматический PASS. Не прятать внешние требования и цену API-запуска.
3. Реальные переходы к проверке графа, моделям, синхронизации, службам, шаблонам и настройке помощника. Подсвечивать выбранную ноду; предлагать правки с отменой/предпросмотром.
4. Настроенный агент получает выбранный сценарий, ноду/подграф и текущую проверку. Кнопки «объяснить», «типичные связи», «предложить исправление» без составления запроса человеком.
5. Небольшая анимированная схема «исходные данные → обработка → результат», выбор этапа и уменьшение анимации при системном reduced motion. Не заменять объяснения движущимися украшениями.
6. Тот же каталог со стабильными ID и источниками пригоден для будущего портала. Публикация портала — отдельная последующая задача владельца.

## Шесть разных разборов проекта

- Новичок: первый шаг выражен задачей, технический термин объясняется рядом.
- Корректность: отсутствие описания, ошибка чтения и ещё не выполненная проверка различаются.
- Телефон: действия доступны без hover/правой кнопки; контент прокручивается, выход виден.
- Восстановление: неудачный шаг сохраняет уже полученный результат и предлагает конкретный повтор.
- Обучение: есть причина, схема, один эксперимент и ожидаемый результат; агент необязателен.
- Поставка: отдельные уровни «код», «целевая проверка», «живой UI», «пакет», «публичный релиз»; не называть все случаи автоматически решёнными.

## Реализованный проход для 1.2.7

Исходная матрица выше сохраняет формулировки исследования до разработки. Все 50 случаев теперь представлены в `src/shared/guidance/problems.json`: RU/EN, стабильный ID, причина, проверка, ожидаемый результат, конкретный инструмент и источник. Мастер открывается из «Справка → Решить проблему», кнопки холста и меню ноды; предлагает поиск, категории и три шага. Интерактивная схема объясняет роли этапов. После перехода к инструменту кнопка «Вернуться к шагам» восстанавливает место.

Действия ведут к существующей проверке графа, каталогу, синхронизации, службам, шаблонам, конструктору и импорту. Настроенный агент получает выбранный сценарий и объект; исправления предлагаются для просмотра, без немедленной сборки. Без агента доступны встроенные шаги и подключение помощника. На первом экране готовый шаблон задачи расположен перед уроком и чатом. Открытие рабочего окна прекращает вводный тур, чтобы он не заслонял кнопки.

Целевые проверки подтверждают каталог/поиск/восстановление шага/границы объекта/передачу помощнику. В реальном приложении с отдельным профилем через браузер при ширине 390 px проверены поиск, схема IMAGE → VAE Encode → LATENT, возврат с холста, переход к синхронизации, меню ноды и подключение помощника. В отчёте воспроизведены и видны четыре категории: 550 прочитано, 142 ожидают, 0 ошибок, 2 исключения; горизонтального переполнения окна нет. Физический телефон и выполнение генерации этим проходом не проверены.

Это 50 маршрутов помощи, а не 50 автоматических исправлений. Установка сторонних Python-пакетов, изменение внешних путей моделей, гарантированное размещение графа в VRAM и исправление произвольных upstream-ошибок остаются отдельными действиями и ограничениями. Сборка и публикация подтверждаются отдельно от этого исследования.

## Сверка реализации для 1.2.8 (17 ноября 2026)

Все 50 ситуаций находятся в «Решить проблему» на холсте и доступны без модели. Для каждой есть объяснение, предметная подготовка, действие, следующий шаг, ожидаемый результат и переход к связанным нодам. С подключённым помощником можно отдельно запросить объяснение или поручить правку текущего графа. Настройка помощника общая для мастеров и меню нод.

Проверка «Граф» использует соответствующие находки проверки текущего проекта; пустой граф и отсутствующие данные не считаются успехом. «Синхронизация» учитывает ожидающие, ошибочные и исключённые файлы и состояние текущего запуска. «Практическая проба» даёт конкретный способ проверки результата человеком. Качество изображения, работа чужого расширения и физический сенсор не определяются по одной структуре графа. Завершение требует подтверждения ожидаемого результата; изменение графа снимает прежнее подтверждение.
