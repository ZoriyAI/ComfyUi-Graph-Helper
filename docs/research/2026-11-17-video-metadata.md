# Bounded video workflow extraction / Ограниченное чтение видеометаданных

The video import path uses one asynchronous reader for desktop positional reads and browser `File.slice`. It walks MP4/MOV metadata containers and Matroska/WebM Segment/SeekHead/Tags, skipping encoded payloads. The design follows the [Matroska element specification](https://www.matroska.org/technical/elements.html) for relative seek positions and tag structure, and cross-checks container layout against the [FFmpeg MOV demuxer](https://github.com/FFmpeg/FFmpeg/blob/master/libavformat/mov.c). No upstream parser code is copied.

Limits: 8 MiB extracted metadata, 16 MiB total reads, 20,000 elements, nesting depth 12 and 10 seconds. Individual payload reads are at most 256 KiB. Cancellation interrupts a stalled read. Compressed MOV metadata is refused; it is not inflated. Unsafe integer sizes, truncated structures, malformed seek targets and excessive metadata fail with a translated explanation. Asynchronous opening checks the original graph revision before committing, so another edit is preserved.

Verification on 17 November 2026:

- MP4, MOV, MKV and WebM files generated by installed FFmpeg all return the embedded workflow through the built desktop reader. This is CPU file/container qualification, not AI video generation.
- Virtual 5 GiB MP4 and 3 GiB Matroska fixtures read under 2 KiB and skip media ranges. The Matroska fixture includes an unknown-size Cluster and a relative SeekHead reference.
- A real sparse 128 MiB MP4 opens on desktop and in a paired touch-enabled Chromium browser. The browser reads and posts under 4 KiB. This is emulated touch, not a physical phone claim.
- Cancellation, changed-graph refusal, named MP4 metadata, uppercase Matroska tags, length/count budgets and normal JSON/PNG/WebP import regressions passed. No read operation installs codecs, executes file contents or changes the source media.

Evidence is retained locally in `audit-work/desktop/md-completion-audit/video-*`; regression cases are `tests/unit/videoMetadata.test.ts`, `tests/integration/openFilePaths.test.ts` and `tests/e2e/video-metadata.test.ts`.

Русский: общий асинхронный механизм читает метаданные MP4/MOV и Matroska/WebM с диска или через `File.slice`, пропуская кадры. Пределы: 8 МиБ результата, 16 МиБ чтения, 20 000 элементов, глубина 12, 10 секунд; блок чтения до 256 КиБ. Есть отмена, отказ повреждённой структуры и проверка ревизии холста перед импортом. Сжатые метаданные MOV не распаковываются. Четыре контейнера, созданные FFmpeg, прочитаны; виртуальные файлы 5/3 ГиБ и настоящий sparse-файл 128 МиБ подтверждают пропуск медиаданных. В подключённом Chromium прочитано и отправлено меньше 4 КиБ. Это проверка файлов и эмулированного сенсорного интерфейса, без заявления о генерации AI-видео или физическом телефоне.
