# NodeWise Studio 1.2.0

Open the running app from your phone or tablet over Wi-Fi. The browser shares the computer's project and assistant,
with a layout that fits a phone, tablet or desktop. This version also preserves lesson edits during saves and imports,
tracks explanation changes in saved projects, and reports incomplete secret removal.

## Connect a phone

1. Start NodeWise Studio on the computer. Open **Settings → Browser access**.
2. Enable **Allow browser access**, select the computer's Wi-Fi or LAN address and a port, then save.
3. Open the same settings section and choose **Pair a device**. On the phone, open the displayed address or scan the
   QR code, then enter the pairing code. Keep the app running and both devices on a network where they can reach
   each other.

Browser access is off by default. The code lasts five minutes and can be used once. Connected devices can be revoked
on the computer. Disabling access or closing the app disconnects them. Use the computer's network address rather than
`127.0.0.1`, which only reaches the device on which it is opened. The connection uses HTTP and is intended for trusted
local networks. The app does not configure the router or firewall.

## The same project on both screens

- Changes to the graph appear on the computer and in the browser. Conflicting edits are rejected so a stale browser
  command cannot overwrite newer changes.
- The browser uses the assistant configured on the computer. Provider keys remain on the host.
- Open the canvas, library, assistant and properties as separate panels on a small screen. Portrait and landscape
  layouts support touch.
- Upload a project or workflow from the browser, and download the current project or workflow to the phone.
  Browser uploads are limited to 11 MiB.
- Configure network access, native folders and stored keys on the computer.

[Browser access guide](../wiki/start/Browser-Access.md)

## Fixes since 1.1.0

- Editing a lesson preserves its other translation. Delayed saves preserve newer edits and report failed writes.
- Importing a lesson pack is atomic: failed imports restore the existing files and retain the draft for another try.
- Explanation changes mark the project as changed, while clean files saved by 1.1.0 remain compatible.
- Compressed workflow metadata in PNG files has bounded decompression; oversized metadata reports a clear error.
- Clearing stored secrets reports files that could not be removed or verified.
- Background synchronization discards retries from an old source after the connection changes.

## Downloads

Linux x64 packages built for this release: `.deb`, portable `.tar.gz` with `run.sh`, `install.sh` and `uninstall.sh`,
and AppImage. The release also includes `install-windows.ps1`, `install-macos.sh`, a component list and `SHA256SUMS`.
The install scripts build from this tag's source on Windows or macOS; they are not prebuilt Windows or macOS apps.
There is no RPM or ARM package in this release. These packages were built locally; no GitHub build provenance
attestation is claimed.

Close the previous app before starting the update. Your existing projects and settings are kept.

## Verification limits

The LAN feature was checked against the packaged Linux app with a mobile-sized Chromium browser, including pairing,
shared graph changes and shutting down access. A physical phone on a home Wi-Fi network has not yet been tried.
Real ComfyUI and physical Windows/macOS device verification remain outside these checks.
