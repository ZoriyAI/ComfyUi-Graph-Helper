# 1.2.7 — clearer synchronization and practical guided help

Synchronization automatically tries another way to read model headers and reports **read, pending, failed and excluded** files separately. The new **Solve a problem** guide covers 50 practical situations with an explanation, an interactive diagram and a route to the relevant tool.

- Optional missing safetensors metadata no longer prevents reading a valid header. If the metadata server disconnects or rejects a large header, the application can use the MCP file reader: a bounded header only, without loading model weights. Earlier errors of these kinds are reconsidered once; your exclusions remain.
- Author descriptions beside model files are read independently of header failures. A failed header remains failed while the useful description is retained. Untouched files count as pending; the report no longer says that everything else was read.
- **Help → Solve a problem**, the canvas and node menus open 50 situations covering missing nodes and models, compatibility, memory, LoRA, images, masks, subgraphs, phones, Ollama and other tasks. Search and categories lead through understanding, checking and taking action. Interactive diagrams explain the stages; **Continue the steps** restores your place after using a tool.
- Node menus offer common connections and a proposed repair. A configured assistant receives the object context; repairs remain reviewable proposals. Built-in guidance works without an assistant and offers a route to connect one.
- The first screen starts with a task template. The guide fits narrow screens with scrollable content and reachable close controls. Fixed an assistant panel that could remain hidden on phones, and an introductory tour that could cover a working dialog. Motion respects reduced-motion preferences.

The 50 routes are based on official documentation and user reports. Their original source-linked matrix is in `docs/research/2026-11-16-fifty-user-problems.md`. They explain actions and open tools; they do not automatically install third-party packages, configure every external ComfyUI setting or fix every possible error.

Checked header recovery, independent descriptions, accounting, guidance routes and context handoff. The actual application was reviewed through its browser interface on an isolated profile at 390px and desktop widths. Physical-phone behavior, arbitrary graph generation and a new sync on the user's installed application are outside this proof.

Linux x64: `.deb`, AppImage, portable `.tar.gz`, source-build scripts for Windows/macOS, SBOM and checksums. Close the old application before installing. After updating, open **Synchronization → Problems and repair** and retry non-excluded files.
