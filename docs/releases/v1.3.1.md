# 1.3.1

**Delivery note:** these fixes are included in [1.4.0](v1.4.0.md); 1.3.1 was not published separately.
Model synchronization now reads large safetensors headers in small portions before asking the legacy metadata reader. This fixes a reproducible MCP disconnect caused by a 14 MB embedded header and a separate server response limit that rejected larger portions.

- Header reads use 256 KiB portions, with bounds and integrity checks. Model weights are not transferred into NodeWise.
- Native ComfyUI recovery remains available when node definitions were received successfully through MCP.
- A truncated header response is reported for that file without switching to an oversized whole-header request; later files can still be read.
- Author descriptions remain independent of header metadata, and files without embedded descriptions can still be read successfully.
- Existing exclusions stay as you selected them. In **Sync → Problems and repair**, turn off **Skip this file** for files you want to read again, then choose **Retry**.

If the old version has already disconnected the server's internal reader, restart the configured MCP service once through **Settings → Services**, then synchronize. The fix prevents NodeWise from issuing the request that caused this failure; it does not change the installed server or restart ComfyUI automatically.
