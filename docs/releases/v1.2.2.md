# 1.2.2 — catalog synchronization fixes

Synchronization reuses the ComfyUI registry it has already read and can finish model metadata through the verified
ComfyUI origin when MCP's internal reader keeps answering “Not connected” after reconnection.

- Full `/object_info` is read before paged discovery. Its registry replaces redundant class pages: for 3375 classes,
  34 extra requests are removed, each of which could trigger a filesystem scan on the server. Packs and models
  still refresh. Paged discovery remains available when full definitions cannot be read.
- Classes with unsupported parameter definitions remain discoverable; readable controls and widget ordering stay intact.
- After bounded MCP reconnection, model headers can continue through `/view_metadata` at the ComfyUI origin whose
  catalog was successfully read during this run. Origin and cancellation guards remain; MCP credentials are never
  forwarded to ComfyUI. Fresh subsequent syncs do not reread already completed headers.
- An unavailable fallback route or a failed request does not count as a completed header. If both readers fail,
  the app retains a warning or error rather than assuming a model is corrupt from a dropped connection alone.

Linux x64: `.deb`, AppImage and portable `.tar.gz`, plus Windows/macOS source installers, component inventory and
`SHA256SUMS`. Close the previous app before installing. Projects and settings are retained.

Verified against local fixture servers and a 3375-class reproduction, including connection loss, repeat runs,
unsupported routes, origin/cancellation guards and catalog preservation. The owner's live server has not been
exercised. This update does not change an installed ComfyUI or its MCP service.
