# NodeWise Studio 1.2.3 — metadata sync recovery

Fixes a model-metadata sync that repeatedly stopped at the same file after MCP reported `Not connected`. ComfyUI's native metadata route also returns HTTP 404 for headers above its 1 MiB limit or without embedded metadata. Previously, failure on that first fallback file stopped the entire pass.

Recovery now checks at most five other catalogued headers. It switches to the accepted ComfyUI address only after a real metadata response, reports unavailable files individually, and continues reading healthy files. Probe results are reused across batches; a batch size of one and later retries of the last unavailable file are supported. The unreadable-file report remains available in Settings → Sync.

An unsupported route, an offline server, or cancellation does not become a successful read. Large or absent metadata is not invented or marked complete. This fixes the application's recovery behavior; it does not restart or repair an MCP server's internal reader.

Validated with targeted synchronization tests, including a disconnected MCP reader followed by a native 404 and healthy remaining headers, unsupported routes, network loss, cancellation and repeated sync. The application does not modify model files. Linux x64: deb, AppImage and portable archive; source build scripts for Windows/macOS.
