# NodeWise Studio 1.2.4 — sync repair and model controls

Sync problems now have a separate **Sync → Sync problems and repairs** window. It collects connection warnings, unread and excluded files, with retry and direct-file repair. A skipped file can be retried immediately; a successful read removes its exclusion.

Select the same safetensors file on your device to recover its header metadata when the server cannot read it. Only the prefix and a bounded header are read, without loading or uploading weights. Name, size and catalog revision are checked. A valid file without embedded metadata is recorded honestly; existing sidecar descriptions are retained. History explains large or absent headers.

**Settings → Assistant** replaces the context number with Automatic and task modes, plus explained response styles. Ollama configuration is applied through its native API, then the app loads the model and verifies the actual context and requested generation settings. The chat warning offers **Configure automatically**, including saving the verified result. Model defaults, templates and stop tokens are retained unless a supported style override is explicitly chosen.

The model monitor shows loaded models, allocated memory/VRAM and actual context. Refresh, load the selected model, stop the assistant response or unload a model without deleting it. Load/unload success is checked against server state. Phone layouts use larger controls and a scrollable repair dialog.

The compact tool set now keeps resource assessment and tools relevant to requested blueprints/subgraphs, while retaining Ask/Build permission boundaries.

Configuration and model lifecycle controls require Ollama's native API; generic OpenAI-compatible endpoints and OS service start/stop are not managed by these controls. Automatic context sizing accounts for request size and the model limit, but available RAM/VRAM still determines whether the model can load. An unconfirmed action is reported as a failure and does not switch the assistant configuration.

Checked with focused unit tests, isolated Electron scenarios for file repair and automatic model configuration, desktop/phone screenshots, type checks and Linux packaging. Linux x64: deb, AppImage and portable archive. The checks do not modify a user's model files or services.
