# 1.2.8

The assistant now carries out ordinary requests on your existing graph, including clearing the canvas, building several variants and editing inside earlier subgraphs. The fifty problem guides have concrete preparation, actions and result checks; recovery and memory controls make the transition to ComfyUI clearer.

- **Ask for the change directly.** Assistant is the default mode. Explain stays read-only; Build remains available for construction. Clearing preserves history, and requested edits work across turns. Empty graph containers are described as unfinished until populated.
- **Make room for ComfyUI.** Settings and the export handoff can pause chat and background translation, unload the local Ollama models this app used, and verify the result. Automatic release on desktop exit is on by default. Other model names and the shared service stay running. Unsupported or failed unloading is reported with retry.
- **Practical guides.** All 50 situations have specific preparation and next actions, relevant node shortcuts and filtered starting templates where appropriate. Graph and synchronization checks use current data. Practical outcomes need the person’s confirmation; that confirmation expires when the graph changes.
- **Recover saved work.** Canvas, chat and lesson failures show retry controls. Pending chat starts and writes are handled during cancellation or clearing; a late history response cannot resurrect cleared messages. Failed assistant answers remain excluded from model context after reopening. An answer no longer steals focus.
- **Keep settings and edits.** Narrow preference updates preserve concurrent changes. Delayed additions stay tied to their original graph and level. Lessons distinguish unread LoRA metadata from confirmed empty trigger words and filter replacement models by the lesson’s requirements.
- **Protect recovery copies.** New migration backups omit credentials. Forgetting keys and clearing project chat also reach known older copies while preserving graphs. An unreadable copy produces an incomplete result rather than a false success. Older recovery copies are retained.
- **A clear phone canvas.** The welcome screen has a visible **Go to the canvas** button. Your device remembers dismissal; the empty canvas toolbar can reopen it.
- **Documentation and delivery.** Corrected old assistant limits, bilingual navigation, interface terms and release records. The release workflow waits for checks and Windows/macOS source installers for the exact planned source.

The guides work without an assistant. Automatic model unloading currently requires Ollama’s native API; other servers retain their own controls. Generated workflows still run in ComfyUI, and graph checks or memory estimates do not prove image quality or peak GPU use. Physical-device and platform-specific acceptance are recorded separately from automated checks.
