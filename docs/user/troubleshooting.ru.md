# Решение проблем

## Ключ или токен не сохраняется: «Хранилище паролей здесь недоступно»

Приложение хранит ключи в хранилище паролей системы (GNOME Keyring или KWallet). Если хранилища нет или оно закрыто, ключ живёт только до закрытия приложения.

Что сделать:

1. Откройте «Настройки ▸ Приватность ▸ Хранилище паролей» и выберите то, что есть у вас: GNOME Keyring (`gnome-libsecret`) или KWallet.
2. Если хранилища нет совсем, установите его: `sudo apt install gnome-keyring`, затем выйдите из системы и войдите снова.
3. Можно и без хранилища: «Запомнить в папке приложения» записывает ключ в папку приложения без шифрования. Файл доступен только вашему пользователю. Облачный ключ может тратить деньги, поэтому так стоит делать только на своём компьютере.

## После синхронизации библиотека пустая

1. Посмотрите на индикатор синхронизации справа вверху. Он говорит, что случилось: сервер недоступен, вход истёк, ComfyUI не запущен или часть каталога не прочитана.
2. Убедитесь, что запущены и ComfyUI, и MCP-сервер рядом с ним.
3. В «Настройки ▸ Подключение» нажмите «Проверить» рядом с адресом. Если сервер просит вход, выберите «Токен» или «Вход через браузер».
4. Нажмите «Синхронизация ▸ Синхронизировать сейчас».
5. Если не помогло, «Справка ▸ Скопировать диагностику» кладёт в буфер отчёт без ключей и токенов. Его можно вставить в сообщение.

## Своя модель отвечает невпопад или обрывает ответ

Модель на вашем сервере читает только то, что помещается в её окно контекста. Ollama по умолчанию даёт маленькое окно: 4 тысячи токенов, если видеопамяти меньше 24 ГБ. Запрос помощника вместе с инструментами занимает от 3 до 6 тысяч токенов, всё лишнее сервер молча отбрасывает.

Приложение это замечает и показывает в чате карточку с двумя числами. «Настройки ▸ Помощник ▸ Проверить связь» сразу показывает окно, с которым загружена модель.

Что сделать: увеличьте окно на сервере хотя бы до 16 384. Для Ollama задайте переменную `OLLAMA_CONTEXT_LENGTH=16384` и перезапустите сервер, или задайте `num_ctx` у модели.

## При запуске ошибка «Running as root without --no-sandbox is not supported»

Приложение запущено от имени root, например через `sudo`. Так его запускать нельзя: защита Chromium работает только у обычного пользователя.

Что сделать: запустите приложение из меню или командой `comfyui-graph-builder` без `sudo`.

## ComfyUI на другом компьютере

Приложение может работать с ComfyUI на другом компьютере.

- Адрес MCP-сервера на другом компьютере должен начинаться с `https://`. Адрес `http://` подходит только для сервера на этом же компьютере (`localhost`, `127.0.0.1`).
- Полное описание нод (порты и поля) приложение берёт у самого ComfyUI, если сервер называет его адрес. С другого компьютера этот адрес часто не виден. Тогда впишите его в поле «Адрес ComfyUI» в «Настройки ▸ Подключение», например `http://192.168.1.50:8188`.
- Если ComfyUI недоступен вовсе, можно загрузить список нод из файла: «Файл ▸ Загрузить список нод из файла…» и файл `object_info`, сохранённый из ComfyUI.

## При запуске: «Файл с данными приложения повреждён»

Приложение не смогло прочитать свою базу. «Начать с пустыми данными» откладывает повреждённый файл в сторону под именем `comfyui-desktop.db.damaged-<дата>` в папке `~/.config/comfyui-graph-builder` и начинает с чистой базы. Ничего не удаляется. Сохранённые файлы проектов и workflow не затронуты: откройте их снова через «Файл ▸ Открыть проект». «Открыть папку» показывает папку с данными, «Выйти» закрывает приложение, ничего не меняя.

Если рядом лежит `comfyui-desktop.db.before-v16.bak` (число может быть другим), это копия базы, сделанная перед последним обновлением. Чтобы вернуться к ней, закройте приложение, уберите из папки файлы `comfyui-desktop.db`, `comfyui-desktop.db-wal` и `comfyui-desktop.db-shm` (если они есть), переименуйте копию в `comfyui-desktop.db` и запустите приложение снова. Приложение снова обновит её до своей версии.

## При запуске: «Ваши данные сохранены более новой версией приложения»

Вы установили версию старше той, что работала с этими данными. Приложение ничего не меняет и закрывается. Установите новую версию снова.

## При запуске: нет места на диске, папка только для чтения или файл занят

- «На диске нет места для данных приложения»: освободите место и запустите приложение снова. Данные сохранены.
- «Приложение не может писать в папку с данными»: проверьте, что папка `~/.config/comfyui-graph-builder` принадлежит вам и диск не защищён от записи.
- «Файл с данными приложения занят другой программой»: закройте её и запустите приложение снова.

Если место на диске кончилось во время работы, приложение скажет, что изменение не сохранено. Освободите место и повторите.

## Где посмотреть подробности

- «Справка ▸ Открыть папку журналов»: журнал приложения.
- «Справка ▸ Журнал общения с помощником…»: что ушло модели и что она ответила.
- «Справка ▸ О программе ▸ Скопировать сведения»: версия приложения и системы для сообщения об ошибке.
